# ০৩. Introduction to JSON — why, how and when?

কল্পনা করো তুমি একটা আন্তর্জাতিক কার্গো কোম্পানির মালিক। তোমার জাহাজে বিভিন্ন দেশ থেকে বিভিন্ন ধরনের মালামাল আসে — কেউ পাঠায় বাক্সে, কেউ বস্তায়, কেউ খোলা অবস্থায়। প্রতিবার নতুন প্যাকেজিং দেখে বুঝতে হয় এর ভেতরে কী আছে, কীভাবে খুলতে হয় — এটা ভীষণ অদক্ষ একটা ব্যবস্থা। এই সমস্যার সমাধানে শিপিং ইন্ডাস্ট্রি একটা জিনিস আবিষ্কার করেছিল — **স্ট্যান্ডার্ড কন্টেইনার**। এখন যেকোনো দেশ থেকে যেকোনো মালামাল একই আকৃতির কন্টেইনারে ভরে পাঠানো যায়, আর পৃথিবীর যেকোনো বন্দরের ক্রেন সেটা তুলতে-নামাতে জানে, কারণ কন্টেইনারের গঠনটা সবার কাছেই পরিচিত।

সফটওয়্যার জগতেও ঠিক এই একই সমস্যা ছিল। একটা সিস্টেম হয়তো JavaScript-এ লেখা, আরেকটা Python-এ, আরেকটা Java-তে — কিন্তু তাদের একে অপরের সাথে ডেটা আদান-প্রদান করতে হয়। যদি প্রতিটা ভাষা তার নিজস্ব পদ্ধতিতে ডেটা সাজায়, তাহলে একটা সিস্টেমের ডেটা আরেকটা সিস্টেম বুঝতেই পারবে না। এই সমস্যার সমাধান হিসেবে এসেছে **JSON (JavaScript Object Notation)** — ডেটা প্যাকেজিং-এর একটা সার্বজনীন "স্ট্যান্ডার্ড কন্টেইনার" ফরম্যাট। নাম JavaScript-এর হলেও, আজকে প্রায় প্রতিটা প্রোগ্রামিং ভাষা JSON পড়তে আর লিখতে পারে।

JSON-এর গঠনটা আসলে আমাদের চেনা — Module 4-এ শেখা JavaScript object আর array-এর গঠনের সাথে প্রায় হুবহু মিল। একটা সাধারণ JSON দেখা যাক:

```json
{
  "name": "রহিম",
  "age": 25,
  "isLoggedIn": true,
  "hobbies": ["ক্রিকেট", "বই পড়া"],
  "address": {
    "city": "ঢাকা",
    "zip": "1200"
  }
}
```

লক্ষ্য করো — key-value জোড়া (`"name": "রহিম"`), array (`hobbies`), এমনকি nested object (`address`) — সবকিছুই এখানে আছে। এই জন্যই JSON-কে বলা হয় ডেটা আদান-প্রদানের **lingua franca** বা সার্বজনীন ভাষা — এটা এতটাই সহজবোধ্য আর নমনীয় যে জটিল থেকে জটিল ডেটাও এভাবে সাজানো যায়, আবার যেকোনো সিস্টেম সেটা পড়তে পারে।

কিন্তু এখানে একটা সূক্ষ্ম কিন্তু গুরুত্বপূর্ণ পার্থক্য বোঝা দরকার — JSON আর JavaScript object একই জিনিস না। JSON হলো একটা **টেক্সট ফরম্যাট** — মানে এটা আসলে একটা স্ট্রিং, যেটা নেটওয়ার্কের মধ্য দিয়ে পাঠানো যায়, ফাইলে সংরক্ষণ করা যায়। অন্যদিকে JavaScript object হলো মেমোরিতে থাকা একটা লাইভ ডেটা স্ট্রাকচার, যেটার উপর তুমি সরাসরি কাজ করতে পারো। এই দুইয়ের মধ্যে রূপান্তর করার জন্য JavaScript-এ দুইটা built-in পদ্ধতি আছে:

```javascript
const user = {
  name: "রহিম",
  age: 25
};

// JavaScript object থেকে JSON স্ট্রিং বানানো — যখন নেটওয়ার্কে পাঠাতে হবে
const jsonString = JSON.stringify(user);
console.log(jsonString);
// আউটপুট: '{"name":"রহিম","age":25}'
console.log(typeof jsonString); // "string"

// JSON স্ট্রিং থেকে আবার JavaScript object বানানো — যখন ডেটা গ্রহণ করা হবে
const parsedBack = JSON.parse(jsonString);
console.log(parsedBack.name); // "রহিম"
console.log(typeof parsedBack); // "object"
```

`JSON.stringify()`-কে ভাবতে পারো মালামালকে কন্টেইনারে ভরার কাজ হিসেবে — পাঠানোর জন্য প্রস্তুত করা। আর `JSON.parse()` হলো বন্দরে কন্টেইনার খুলে ভেতরের মালামাল বের করার কাজ — গ্রহণকারী পাশে সেটা ব্যবহারযোগ্য object-এ রূপান্তর করা।

এখন প্রশ্ন আসতে পারে — এই "কন্টেইনার খোলা-বন্ধ করার" কাজটা ঠিক কখন হয়? উত্তরটা হলো — প্রায় প্রতিবার, যখনই frontend আর backend-এর মধ্যে ডেটা চলাচল করে। Module 6-এ যখন আমরা POST endpoint বানিয়েছিলাম, তখন `req.body`-তে যে ডেটা পেয়েছিলাম, সেটা Express.js ইতিমধ্যে JSON থেকে JavaScript object-এ পার্স করে দিয়েছিল আমাদের হয়ে। পরের লেসনে আমরা ঠিক এই যাত্রাটা — frontend থেকে backend পর্যন্ত JSON-এর সম্পূর্ণ পথ — ধাপে ধাপে অনুসরণ করবো।
