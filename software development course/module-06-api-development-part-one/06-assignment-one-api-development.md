# ০৬. Assignment: One API Development

এতক্ষণ আমরা যা শিখেছি, সেগুলো ছোট ছোট টুকরো টুকরো উদাহরণে দেখেছি — কখনো একটা `/tasks` রুট, কখনো একটা `if` দিয়ে ভ্যালিডেশন। কিন্তু বাস্তব দক্ষতা তৈরি হয় তখনই, যখন এই সব টুকরো একসাথে বসিয়ে নিজের হাতে একটা সম্পূর্ণ, কার্যকর জিনিস বানানো যায় — ঠিক যেমন একজন ছুতোর মিস্ত্রি আলাদা আলাদা কৌশল শেখার পর, একদিন সত্যিকারের একটা আলমারি বানিয়ে ফেলে, প্রথম থেকে শেষ পর্যন্ত নিজের হাতে। এই লেসনটা সেই দিন — এখন তোমার পালা।

**তোমার কাজ:** একটা "Notes API" বানাও — এমন একটা ব্যাকএন্ড সিস্টেম, যেখানে ব্যবহারকারী ছোট ছোট নোট তৈরি করতে পারবে, সব নোট দেখতে পারবে, আর নির্দিষ্ট একটা নোট মুছে ফেলতে পারবে। এটা শুনতে সাধারণ মনে হলেও, এর ভেতরে এই পুরো মডিউলে শেখা প্রতিটা ধারণা লুকিয়ে আছে।

প্রথমেই বসে চিন্তা করো একটা "Note"-এর মডেল কেমন হওয়া উচিত — ঠিক যেমন আমরা আগের লেসনে Task মডেল নিয়ে ভেবেছিলাম। একটা নোটের কী কী বৈশিষ্ট্য থাকা দরকার? নিশ্চয়ই একটা লেখা বা বিষয়বস্তু (`content`) থাকবে, যেটা ছাড়া একটা নোট অর্থহীন। হয়তো একটা `id` থাকবে, যেটা সার্ভার নিজে থেকেই বসাবে। আর হয়তো একটা `createdAt` থাকবে, যাতে বোঝা যায় নোটটা কখন তৈরি হলো। মডেলটা কাগজে বা মাথায় স্পষ্ট করে নেয়ার পরই কোডে হাত দাও — এটাই এই মডিউলের সবচেয়ে গুরুত্বপূর্ণ শিক্ষা।

তারপর routing সাজাও। তোমার অন্তত এই তিনটা endpoint থাকা দরকার:

- `GET /notes` — সব নোটের তালিকা ফেরত দেবে
- `POST /notes` — নতুন একটা নোট তৈরি করবে, request body থেকে `content` নিয়ে
- `DELETE /notes/:id` — নির্দিষ্ট `id`-এর নোটটা মুছে ফেলবে

চাইলে আরেকটা বাড়তি endpoint যোগ করে চ্যালেঞ্জ বাড়াতে পারো — `GET /notes/:id`, যেটা একটা নির্দিষ্ট নোট খুঁজে বের করে দেখাবে। এভাবেই একটা ছোট, বাস্তব RESTful API-এর গঠন তৈরি হয়ে যাবে, ঠিক যেমনটা আমরা Routing লেসনে দেখেছিলাম।

`POST /notes` endpoint বানানোর সময় মনে রাখতে হবে দুটো জিনিস — প্রথমত, `express.json()` middleware চালু আছে কিনা, নইলে `req.body` খালি আসবে। দ্বিতীয়ত, ভ্যালিডেশন। কোনো অবস্থাতেই ধরে নিও না যে ক্লায়েন্ট সবসময় সঠিক ডেটা পাঠাবে। যদি `content` না থাকে, বা সেটা খালি স্ট্রিং হয়, বা সেটা string না হয়ে অন্য কোনো টাইপ হয় — প্রতিটা ক্ষেত্রে `400 Bad Request` ফেরত দিতে হবে, স্পষ্ট একটা বার্তাসহ যাতে বোঝা যায় ঠিক কী ভুল হয়েছে।

`DELETE /notes/:id` endpoint-এ একটা গুরুত্বপূর্ণ প্রশ্নের মুখোমুখি হবে — যদি ক্লায়েন্ট এমন একটা `id` পাঠায় যেটা আসলে অস্তিত্বই নেই, তখন কী করবে? এখানেই status code-এর জ্ঞান কাজে লাগবে — এটা কোনো সার্ভার-সমস্যা না (তাই `500` না), এটা এমন একটা অনুরোধ যেটা মেলে না কোনো বাস্তব রিসোর্সের সাথে — মনে করে দেখো কোন কোডটা ঠিক এই পরিস্থিতির জন্য তৈরি হয়েছিলো।

নিচে একটা কাঠামো দেয়া হলো, যেটা তোমার প্রজেক্ট শুরু করতে সাহায্য করবে — কিন্তু ইচ্ছাকৃতভাবে অসম্পূর্ণ রাখা হয়েছে, বাকিটা তোমার দায়িত্ব:

```javascript
const express = require('express');
const app = express();

app.use(express.json());

const notes = [];
let nextId = 1;

app.get('/notes', (req, res) => {
  // এখানে সব নোট ফেরত দাও
});

app.post('/notes', (req, res) => {
  // এখানে content ভ্যালিডেট করো, তারপর নতুন নোট তৈরি করো
});

app.delete('/notes/:id', (req, res) => {
  // এখানে id দিয়ে নোট খুঁজে বের করো, না পেলে যথাযথ status code দাও
  // পেলে সেটা মুছে ফেলো
});

app.listen(3000, () => {
  console.log('সার্ভার চালু আছে port 3000-এ');
});
```

**সম্পন্ন হওয়ার শর্ত (Acceptance Criteria):** তোমার কাজটা তখনই সম্পূর্ণ ধরা হবে, যখন নিচের প্রতিটা আচরণ Postman বা `curl` দিয়ে টেস্ট করে দেখানো যাবে। `POST /notes`-এ সঠিক `content` পাঠালে `201 Created` স্ট্যাটাসসহ নতুন তৈরি হওয়া নোটটা (তার `id` সহ) ফেরত আসবে। `POST /notes`-এ `content` ছাড়া বা খালি `content` পাঠালে `400 Bad Request` আসবে, বোধগম্য একটা বার্তাসহ। `GET /notes` সবসময় এখন পর্যন্ত তৈরি হওয়া সব নোটের একটা array ফেরত দেবে। `DELETE /notes/:id` সঠিক `id` দিলে নোটটা মুছে যাবে আর উপযুক্ত সফলতার status code আসবে; ভুল বা অস্তিত্বহীন `id` দিলে যথাযথ error status code আসবে, `500` নয়। আর সবচেয়ে গুরুত্বপূর্ণ — কোডটা পড়ে যেন বোঝা যায় প্রতিটা ধাপ (validation, processing, storage, response) আলাদাভাবে চিন্তা করে লেখা হয়েছে, সব একটা জগাখিচুড়ি `if` ব্লকে গুঁজে দেয়া হয়নি।

এই অ্যাসাইনমেন্টটা শেষ করার পর তোমার হাতে থাকবে একটা কার্যকর, ছোট হলেও প্রকৃত API — আর তার চেয়েও গুরুত্বপূর্ণ, এই পুরো প্রক্রিয়াটা তোমার হাতে-কলমে অভিজ্ঞতা হয়ে যাবে, শুধু পড়া বিষয় হয়ে থাকবে না। তবে বাস্তব-জীবনের API আরও অনেক জটিলতা নিয়ে আসে — একটা নোট আপডেট করা, একাধিক ধরনের রিসোর্সের মধ্যে সম্পর্ক তৈরি করা, বড় তালিকাকে পাতায় পাতায় ভাগ করে দেখানো (pagination), আর ভুল হ্যান্ডলিং আরও সুসংগঠিতভাবে করা। এই সবকিছু নিয়েই আমরা এগিয়ে যাবো পরের মডিউলে — Module 7: API Development Part Two।
