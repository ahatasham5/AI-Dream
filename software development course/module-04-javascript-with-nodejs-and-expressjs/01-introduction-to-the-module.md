# ০১. Introduction to the Module

গত তিনটা মডিউলে আমরা বুঝেছি ওয়েব সার্ভার কী, কেন Node.js ব্যবহার করি, আর বড় ছবিতে কোন কোন টুল কোথায় বসে। এবার সময় হয়েছে হাতের কাজে ফেরার — আমরা Module 2-এর সেই ছোট্ট, একটামাত্র ফাইল পাঠানো সার্ভারটাকে বড় করে তুলবো, এমন একটা সার্ভারে রূপান্তর করবো যেটা সত্যিকারের অনেক ধরনের অনুরোধ সামলাতে পারে।

মনে করে দেখো, Module 2-এ আমরা `http` মডিউল ব্যবহার করে যে সার্ভার লিখেছিলাম, সেটা যা রিকোয়েস্টই আসুক না কেন, সবসময় একই জবাব দিতো। যদি আমরা চাই `/home` চাইলে এক জিনিস দেখাবে, `/about` চাইলে আরেক জিনিস — তাহলে আমাদের নিজে থেকে `request.url` পরীক্ষা করে if-else এর একটা লম্বা শৃঙ্খল লিখতে হবে। ছোট প্রজেক্টে এটা চলতে পারে, কিন্তু বড় প্রজেক্টে এই if-else শৃঙ্খল দ্রুত অপরিচালনাযোগ্য হয়ে ওঠে।

এই সমস্যাটার একটা পরিষ্কার, সুশৃঙ্খল সমাধান দেয় **Express.js** — যেটা Node.js-এর সবচেয়ে জনপ্রিয় web framework। এই মডিউলে আমরা প্রথমবারের মতো Express.js ব্যবহার শুরু করবো, কিন্তু তার আগে কয়েকটা JavaScript-এর মৌলিক ধারণা ঝালিয়ে নেবো (callback, let/var/const) — কারণ এই ধারণাগুলো ছাড়া Express.js-এর কোড পড়লে অনেক জায়গায় "এটা কেন এভাবে লেখা" প্রশ্নটা অমীমাংসিত থেকে যাবে।

## এই মডিউলে যে প্রশ্নগুলোর উত্তর খুঁজবো

- JavaScript-এর basic ধারণাগুলো (variable, callback) ব্যাকএন্ড কোডে ঠিক কীভাবে ব্যবহৃত হয়?
- Express.js কী সমস্যা সমাধান করে, যেটা শুধু `http` module দিয়ে কঠিন?
- ব্রাউজার ছাড়া কীভাবে একটা API টেস্ট করা যায় (Postman, Thunder Client)?
- URL-এর ভেতরে ডেটা পাঠানোর দুটো আলাদা পদ্ধতি (Query Parameter বনাম Path Parameter) কী, কখন কোনটা ব্যবহার করবো?
- একটা backend service কীভাবে নিজেই আরেকটা backend-এর "client" (ব্যবহারকারী) হতে পারে?
- Python-এর FastAPI আর Node.js-এর Express.js — এই দুটো ভিন্ন ভাষার framework কেন প্রায় একই রকম দেখতে লাগে?

চলো শুরু করি — প্রথমে ফিরে যাই কয়েকটা JavaScript-এর মৌলিক ধারণায়, যেগুলো এখন থেকে আমাদের প্রতিটা লেসনে বারবার ব্যবহৃত হবে।
