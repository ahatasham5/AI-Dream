# ০৩. Purpose of Core Modules in Backend System

Module 2-তে আমরা দুইটা জিনিস ব্যবহার করেছিলাম যেগুলো নিয়ে তেমন কথা বলিনি — `http` আর `fs`। এই দুটোকে বলা হয় Node.js-এর **core module** বা **built-in module** — মানে এগুলো Node.js-এর সাথেই আসে, আলাদা করে ইনস্টল (`npm install`) করতে হয় না। এই লেসনে আমরা বুঝবো, এই "core module" ধারণাটার পেছনের যুক্তি কী, আর কেন Node.js এভাবেই ডিজাইন করা হয়েছে।

## সমস্যাটা কল্পনা করি

ধরো Node.js যদি একদম "খালি" থাকতো — কোনো built-in সুবিধা ছাড়াই, শুধু ভাষার মৌলিক জিনিস (variable, function, loop) থাকতো। তাহলে প্রতিবার একটা ফাইল পড়তে চাইলে, তোমাকে অপারেটিং সিস্টেমের সাথে সরাসরি "কথা বলার" নিয়ম নিজে থেকে লিখতে হতো — যেটা অত্যন্ত জটিল, এবং প্রতিটা OS-এ (Windows, Mac, Linux) আলাদা আলাদাভাবে কাজ করে।

Node.js এই জটিলতা একবার সমাধান করে, একটা সহজ ইন্টারফেসের পেছনে লুকিয়ে দিয়েছে — এটাই core module-গুলোর কাজ। তুমি লেখো `fs.readFile('index.html', ...)`, আর Node.js নিজে ভেতরে ভেতরে বুঝে নেয় সেটা Windows-এ কীভাবে করতে হবে, নাকি Linux-এ কীভাবে করতে হবে — তোমাকে এই পার্থক্য নিয়ে মাথা ঘামাতে হয় না।

```mermaid
    You["তোমার কোড: <br/> fs.readFile(...)"] --> Node["Node.js Core Module (fs)"]

    Node --> Mac["macOS-এর নিয়ম অনুযায়ী কাজ করে"]
    Node --> Lin["Linux-এর নিয়ম অনুযায়ী কাজ করে"]
```

## কিছু গুরুত্বপূর্ণ Core Module, যেগুলো সামনে বারবার আসবে

| Module | কাজ | এই কোর্সে কোথায় কাজে লাগবে |
|---|---|---|
| `http` | সার্ভার তৈরি করা, request/response সামলানো | Module 2-এ ব্যবহার করেছি |
| `fs` | ফাইল পড়া/লেখা | HTML পাঠানো, লগ ফাইল লেখা |
| `path` | ফাইল পাথ নিয়ে কাজ করা (OS-নির্ভরতা এড়িয়ে) | প্রজেক্ট স্ট্রাকচার সাজানোর সময় |
| `os` | কম্পিউটার সম্পর্কে তথ্য (CPU, মেমরি) | Process/Thread নিয়ে কাজ করার সময় (Module 10) |
| `crypto` | এনক্রিপশন, হ্যাশিং | পাসওয়ার্ড নিরাপদ রাখার সময় (Module 12, JWT) |
| `events` | কাস্টম ইভেন্ট তৈরি করা | Node.js-এর ভেতরের অনেক কিছুর ভিত্তি |

লক্ষ্য করো — `crypto` module-টা আমরা এখনই ব্যবহার করবো না, কিন্তু Module 12-তে যখন আমরা পাসওয়ার্ড হ্যাশ করা শিখবো, তখন এটাই ব্যবহার করবো। এই মুহূর্তে শুধু নামটা চিনে রাখো — "ও, তার মানে Node.js-এর ভেতরেই এনক্রিপশনের জন্য বিল্ট-ইন সুবিধা আছে, বাইরে থেকে কিছু আনতে হয় না।"

## Core Module বনাম External Package — পার্থক্যটা এখনই স্পষ্ট করে নেই

সামনের মডিউলগুলোতে আমরা `express` এর মতো প্যাকেজ ব্যবহার করবো, যেগুলো Node.js-এর সাথে built-in আসে না — সেগুলো `npm install` দিয়ে আলাদা করে আনতে হয়। পার্থক্যটা মনে রাখার সহজ উপায়:

- **Core Module** — Node.js নিজেই তৈরি করে, নিজের সাথেই বিতরণ করে। `require('http')` লিখলেই কাজ করবে, কোনো ইনস্টলেশন লাগে না।
- **External Package (npm package)** — অন্য কোনো ডেভেলপার বা কোম্পানি তৈরি করেছে, npm registry-তে প্রকাশ করেছে। ব্যবহারের আগে `npm install <package-name>` দিয়ে ইনস্টল করতে হয়।

এই পার্থক্যটা মাথায় স্পষ্ট থাকলে, সামনে যখন কোনো নতুন `require(...)` দেখবে, তুমি সহজেই বুঝতে পারবে এটা কি Node.js-এর নিজের কিছু, নাকি বাইরে থেকে ইনস্টল করা কোনো প্যাকেজ — আর সেই বোঝাটাই তোমাকে সাহায্য করবে ডিবাগ করতে, যদি কখনো "module not found" ধরনের এরর আসে।
