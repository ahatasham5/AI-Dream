# ০৬. অ্যাসাইনমেন্ট: Authentication সহ পার্সোনাল TODO ম্যানেজার

এখন পর্যন্ত আমরা টুকরো টুকরো করে অনেক কিছু শিখেছি — Hashing দিয়ে পাসওয়ার্ড নিরাপদ রাখা, JWT দিয়ে ক্লায়েন্ট Authenticate করা, Express-এ middleware দিয়ে route প্রোটেক্ট করা। এই লেসনটা নতুন কিছু শেখানোর জন্য নয় — বরং এতদিন যা শিখেছো তা একটা বাস্তব, ছোট কিন্তু সম্পূর্ণ প্রজেক্টে প্রয়োগ করার চ্যালেঞ্জ। ভাবো এটাকে একটা পরীক্ষা হিসেবে, যেখানে কোনো ধাপে ধাপে কোড দেয়া হবে না — শুধু কী বানাতে হবে আর কেন, তা বলা থাকবে। বাকিটা তোমার।

## প্রজেক্টের বর্ণনা

তুমি বানাবে একটা **Personal TODO Manager API** — যেখানে প্রতিটা ব্যবহারকারীর নিজস্ব, আলাদা TODO তালিকা থাকবে, আর কেউ অন্য কারো তালিকা দেখতে বা বদলাতে পারবে না, যদি না সে সেই ব্যবহারকারী হিসেবে লগইন করে থাকে। কোনো ডেটাবেস ব্যবহার করা যাবে না — সব ডেটা (ইউজার আর TODO দুটোই) সাধারণ JavaScript অ্যারে/অবজেক্টে, সার্ভারের মেমরিতে জমা থাকবে। এটা ইচ্ছাকৃতভাবে সহজ রাখা হয়েছে, যাতে তুমি Authentication আর Authorization-এর লজিকের ওপর পুরো মনোযোগ দিতে পারো, ডেটাবেসের জটিলতা নিয়ে চিন্তা না করে।

## যা যা বানাতে হবে

**রেজিস্ট্রেশন ও লগইন।** `POST /register` route বানাও, যেখানে নতুন username/password দিয়ে রেজিস্ট্রেশন করা যাবে। পাসওয়ার্ড অবশ্যই plain text-এ রাখা যাবে না — লেসন ৩-এ শেখা `crypto.scryptSync` (বা `bcrypt`) দিয়ে হ্যাশ করে রাখতে হবে। `POST /login` route বানাও, যেখানে সঠিক username/password দিলে একটা JWT ফেরত আসবে।

**TODO CRUD, কিন্তু Authentication সহ।** নিচের route-গুলো বানাও, প্রতিটাই একটা `authenticateToken` middleware দিয়ে প্রোটেক্ট করা থাকতে হবে:

| Method | Route | কাজ |
|---|---|---|
| POST | `/todos` | নতুন TODO যোগ করা |
| GET | `/todos` | শুধুমাত্র নিজের সব TODO দেখা |
| PUT | `/todos/:id` | নিজের একটা TODO আপডেট করা (যেমন "done" মার্ক করা) |
| DELETE | `/todos/:id` | নিজের একটা TODO মুছে ফেলা |

**সবচেয়ে গুরুত্বপূর্ণ শর্ত** — প্রতিটা TODO যখন তৈরি হবে, সেটার সাথে কোন ব্যবহারকারী তৈরি করেছে সেই তথ্য (যেমন username) জমা রাখতে হবে। আর `GET /todos`, `PUT /todos/:id`, `DELETE /todos/:id` — এই route-গুলোতে অবশ্যই যাচাই করতে হবে যে request পাঠানো ব্যবহারকারীই সেই TODO-র মালিক, নাহলে ৪০৩ Forbidden ফেরত দিতে হবে। এই অংশটাই মূল চ্যালেঞ্জ — শুধু "লগইন করা আছে কিনা" চেক করাই যথেষ্ট না, "এই নির্দিষ্ট রিসোর্সটা এই ব্যবহারকারীরই কিনা" সেটাও চেক করতে হবে।

```mermaid
flowchart TD
    A["Request আসলো Authorization header সহ"] --> B["authenticateToken middleware: টোকেন বৈধ?"]
    B -->|না| C["401/403"]
    B -->|হ্যাঁ| D["req.user সেট হলো"]
    D --> E["Route handler: এই TODO-টা কি req.user-এর?"]
    E -->|না| F["403 Forbidden"]
    E -->|হ্যাঁ| G["কাজ সম্পন্ন করো (আপডেট/ডিলিট/দেখাও)"]
```

## ইঙ্গিত ও পরামর্শ

ডেটা স্ট্রাকচার এরকম সহজ করে সাজাতে পারো:

```js
let users = []; // [{ username, hashedPassword }]
let todos = []; // [{ id, title, done, owner }]
```

`id` তৈরি করার জন্য `crypto.randomUUID()` ব্যবহার করতে পারো (এটাও `crypto` মডিউলেরই একটা ফাংশন)। প্রতিটা এরর কেসে সঠিক Status Code ব্যবহার করতে ভুলো না — Module 6-এ শেখা ৪০০ (ভুল ইনপুট), ৪০১ (লগইন করা নেই), ৪০৩ (পারমিশন নেই), ৪০৪ (TODO খুঁজে পাওয়া যায়নি)। Postman দিয়ে দুইটা আলাদা ব্যবহারকারী রেজিস্টার করে টেস্ট করো — নিশ্চিত হও যে ব্যবহারকারী A কখনোই ব্যবহারকারী B-র TODO দেখতে বা মুছতে পারছে না, এমনকি সে যদি সঠিক TODO `id` অনুমান করেও ফেলে।
