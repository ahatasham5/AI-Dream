# ০১. Module Recap and New Module Introduction

Module 6-এ আমরা প্রথমবারের মতো Express.js দিয়ে "আসল" API বানানো শুরু করেছিলাম। মনে করে দেখো — আমরা শিখেছিলাম status code মানে কী আর কখন কোনটা পাঠাতে হয়, `app.get`/`app.post` দিয়ে কীভাবে routing করা যায়, একটা POST request-এর ভেতরে ঠিক কী কী থাকে (headers, body, params), ব্যাকএন্ডে ডেটা কীভাবে মডেল করে রাখা হয়, আর সবশেষে শিখেছিলাম কীভাবে ইউজারের পাঠানো ডেটা validate করতে হয় — যাতে ভুল বা ক্ষতিকর ডেটা আমাদের সিস্টেমে ঢুকতে না পারে।

এই সবকিছু মিলিয়ে তুমি এখন একটা কাজ করা API বানাতে পারো — একটা রুট, তার ভেতরে কিছু লজিক, একটা রেসপন্স। কিন্তু একটা প্রশ্ন যদি মাথায় আসে — "আমার অ্যাপে যদি ৫০টা রুট থাকে, প্রতিটার ভেতরে যদি ২০ লাইন করে লজিক থাকে, তাহলে পুরো ফাইলটা কেমন দেখাবে?" — উত্তরটা খুব সুখকর না। একটামাত্র `server.js` বা `app.js` ফাইলের ভেতরে হাজার লাইনের কোড, যেখানে routing আর business logic একসাথে জট পাকিয়ে আছে। এটাই বাস্তব জীবনের ব্যাকএন্ড প্রজেক্টে সবচেয়ে সাধারণ সমস্যাগুলোর একটা, আর ঠিক এই সমস্যাটা সমাধান করার জন্যই এই মডিউল।

এই মডিউলে আমরা একটা প্রজেক্টকে ধীরে ধীরে "পরিণত" (mature) একটা স্ট্রাকচারের দিকে নিয়ে যাবো। ভাবতে পারো এটাকে একটা ছোট দোকান থেকে একটা সুসংগঠিত প্রতিষ্ঠানে রূপান্তরের গল্প হিসেবে। প্রথমে আমরা শিখবো **Router** — কীভাবে একগাদা রুটকে ফাইলে ফাইলে ভাগ করে রাখা যায়, ঠিক যেমন একটা বড় অফিসে প্রতিটা বিভাগের নিজস্ব ডেস্ক থাকে। তারপর শিখবো **Controller** — যেখানে আসল কাজের লজিকটা থাকে, রুট থেকে আলাদা করে। এরপর আমরা ঢুকবো **Middleware**-এর জগতে, যেটা এমন একটা ধারণা যা প্রতিটা প্রফেশনাল Express অ্যাপ্লিকেশনের মেরুদণ্ড — প্রতিটা request কোনো না কোনো middleware-এর ভেতর দিয়ে যায়, ঠিক যেভাবে বিমানবন্দরে একজন যাত্রীকে একাধিক চেকপয়েন্ট পার হতে হয়।

মিডলওয়্যার বোঝার পর আমরা সেটাকে ব্যবহার করে দুটো বাস্তব সমস্যা সমাধান করবো — **Rate Limiting** (একজন ইউজার যাতে সার্ভারে অতিরিক্ত request পাঠিয়ে সিস্টেম বিপর্যস্ত করে না ফেলে) আর **Audit Logging** (কে, কখন, কী করলো — সেটার একটা রেকর্ড রাখা)। দুটোই এমন ফিচার, যেগুলো ছোট প্রজেক্টে অনেকে ভুলে যায়, কিন্তু প্রোডাকশনে যাওয়া যেকোনো সিস্টেমে এগুলো প্রায় বাধ্যতামূলক।

```mermaid
flowchart LR
    A[Router\nকোন রুট কোথায়] --> B[Controller\nকী করতে হবে]
    B --> C[Middleware\nপ্রতিটা request-এর জন্য নিয়ম]
    C --> D[Rate Limiting\nবেশি request ঠেকানো]
    C --> E[Audit Logging\nকে কী করলো তার রেকর্ড]
```

এই পুরো যাত্রাটা একটা নির্দিষ্ট লক্ষ্যে এগোচ্ছে — মডিউল শেষে তুমি একটা ছোট কিন্তু বাস্তবসম্মত Express প্রজেক্ট বানাতে পারবে, যেটার routing, business logic, আর security/monitoring লজিক পরিষ্কারভাবে আলাদা আলাদা জায়গায় থাকবে — ঠিক যেভাবে বড় বড় কোম্পানির আসল কোডবেজ সাজানো থাকে।

চলো তাহলে প্রথম ধাপ দিয়ে শুরু করি — Router আসলে কেন দরকার, সেটা বোঝার মধ্য দিয়ে।
