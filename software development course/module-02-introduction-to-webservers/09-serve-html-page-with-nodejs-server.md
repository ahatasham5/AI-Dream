# ০৯. How to Serve HTML Page with Node.js Server?

আমাদের নিজের বানানো সার্ভারটা এখন পর্যন্ত শুধু একটা প্লেইন টেক্সট বার্তা পাঠাচ্ছে — `response.end('হ্যালো...')`। কিন্তু আসল ওয়েবসাইট তো টেক্সট না, HTML পাতা দেখায় — হেডিং, প্যারাগ্রাফ, ছবি, বাটন। এই লেসনে আমরা আমাদের সার্ভারকে শেখাবো কীভাবে একটা প্রকৃত HTML ফাইল খুঁজে বের করে ব্রাউজারের কাছে পাঠাতে হয়।

প্রথমেই বুঝে নেয়া দরকার, ব্রাউজার কীভাবে জানে যে তুমি যে টেক্সট পাঠিয়েছো সেটা সাধারণ লেখা, নাকি HTML? উত্তর হলো, ব্রাউজারকে এটা বলে দিতে হয়, আর সেটা বলা হয় একটা বিশেষ তথ্যের মাধ্যমে, যাকে বলে **header** — বিশেষভাবে `Content-Type` header। আমরা আমাদের response-এ এই header যোগ করবো, বলবো "আমি যা পাঠাচ্ছি সেটা HTML, প্লেইন টেক্সট না।"

চলো প্রথমে একটা HTML ফাইল বানাই। একই ফোল্ডারে `index.html` নামে একটা ফাইল তৈরি করো:

```html
<!DOCTYPE html>
<html>
  <head>
    <title>আমার প্রথম Node.js সাইট</title>
  </head>
  <body>
    <h1>স্বাগতম!</h1>
    <p>এই পাতাটা Node.js সার্ভার থেকে পাঠানো হয়েছে।</p>
  </body>
</html>
```

এখন `server.js` ফাইলটা বদলাই, যাতে এটা প্লেইন টেক্সটের বদলে এই HTML ফাইলটা পড়ে পাঠায়:

```js
const http = require('http');
const fs = require('fs');

const server = http.createServer((request, response) => {
  fs.readFile('index.html', (error, content) => {
    if (error) {
      response.writeHead(500);
      response.end('ফাইল পড়তে সমস্যা হয়েছে');
      return;
    }
    response.writeHead(200, { 'Content-Type': 'text/html' });
    response.end(content);
  });
});

server.listen(3000, () => {
  console.log('সার্ভার চালু আছে port 3000-এ');
});
```

সার্ভার রিস্টার্ট করো (আগেরটা `Ctrl+C` দিয়ে বন্ধ করে, আবার `node server.js` চালাও), তারপর ব্রাউজার রিফ্রেশ করো। এখন দেখবে "স্বাগতম!" লেখা বড় হেডিং হিসেবে দেখাচ্ছে — মানে ব্রাউজার এটাকে সত্যিকারের HTML হিসেবে চিনেছে, প্লেইন টেক্সট হিসেবে না।

এই নতুন কোডে যা যোগ হলো, লাইন ধরে বুঝি:

```js
const fs = require('fs');
```
`fs` মানে **File System** — Node.js-এর আরেকটা বিল্ট-ইন মডিউল, যেটা দিয়ে ডিস্কের ফাইল পড়া/লেখা যায়।

```js
fs.readFile('index.html', (error, content) => { ... });
```
এটা `index.html` ফাইলটা পড়ার চেষ্টা করে। ফাইল পড়া একটা **asynchronous** কাজ — মানে এটা তাৎক্ষণিকভাবে শেষ হয় না, একটু সময় নেয় (ডিস্ক থেকে পড়তে সময় লাগে), তাই আমরা একটা ফাংশন দিচ্ছি যেটা পড়া শেষ হলে চলবে। এই ফাংশনের দুটো সম্ভাব্য ফলাফল — হয় `error` (যদি কোনো সমস্যা হয়, যেমন ফাইলটা খুঁজে না পাওয়া গেলে), অথবা `content` (ফাইলের ভেতরের লেখা, যদি সব ঠিক থাকে)। (Asynchronous ব্যাপারটা নিয়ে বিস্তারিত আলোচনা আসবে Module 5-এ — এখন শুধু এতটুকু বুঝে রাখো যে ফাইল পড়ার কাজ সাথে সাথে শেষ হয় না, তাই এভাবে "পরে কী হবে" বলে দিতে হয়।)

```js
if (error) {
  response.writeHead(500);
  response.end('ফাইল পড়তে সমস্যা হয়েছে');
  return;
}
```
যদি ফাইল পড়তে কোনো সমস্যা হয় (হয়তো ফাইলের নাম ভুল লিখেছো, বা ফাইলটা ডিলিট হয়ে গেছে), আমরা একটা এরর জবাব পাঠাচ্ছি। `500` একটা **status code** — এটা বলে দেয় সার্ভারের নিজের দিক থেকে কিছু ভুল হয়েছে। (Status code নিয়ে বিস্তারিত আলোচনা আসবে Module 6-এ।)

```js
response.writeHead(200, { 'Content-Type': 'text/html' });
```
`200` মানে "সব ঠিক আছে, সফলভাবে জবাব পাঠানো হচ্ছে।" আর `{ 'Content-Type': 'text/html' }` অংশটাই সেই header, যেটা ব্রাউজারকে বলছে "আমি যা পাঠাচ্ছি সেটা HTML হিসেবে পড়ো, প্লেইন টেক্সট হিসেবে না।"

```js
response.end(content);
```
এবার আমরা ফাইলের প্রকৃত কনটেন্টটা পাঠাচ্ছি, আগের মতো হার্ডকোড করা কোনো টেক্সট না।

এই মুহূর্তে আমাদের সার্ভারটা প্রায় একটা প্রকৃত ওয়েব সার্ভারের মতো আচরণ করছে — ডিস্ক থেকে ফাইল পড়ে, সঠিক তথ্যসহ (Content-Type) ব্রাউজারে পাঠাচ্ছে। কিন্তু এখনো একটা বড় সীমাবদ্ধতা আছে — তুমি যাই লিখো ঠিকানার বারে (`/`, `/about`, `/contact`), সবসময় একই `index.html` পাঠানো হবে, কারণ আমরা এখনো `request`-এর ভেতরে কোন পাতা চাওয়া হয়েছে সেটা পরীক্ষা করছি না। এই সীমাবদ্ধতা এখনই সমাধান করবো না — এটা Module 4-এ, যখন আমরা Express.js দিয়ে **routing** শিখবো, তখন সমাধান হবে।

এখন সময় হয়েছে আমাদের ছোট্ট সার্ভারটাকে ইন্টারনেটে সবার জন্য প্রকাশ করার — শুধু localhost-এ নিজের কাছে না রেখে। সেটাই পরের লেসনের বিষয়: cloud আর deployment।
