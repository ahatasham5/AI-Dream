# ০৭. Making a Simple Node.js Webserver

এতক্ষণ আমরা যা দেখেছি সেটা সবই তত্ত্ব আর পর্যবেক্ষণ ছিলো — Live Server নামের একটা রেডি টুল ব্যবহার করে দেখেছি সার্ভার কীভাবে আচরণ করে। এবার সময় এসেছে সেই একই আচরণ, নিজের হাতে, কোনো রেডিমেড টুল ছাড়াই তৈরি করার।

কেন নিজে বানানো দরকার, যেখানে Live Server-এর মতো টুল তো আছেই? উত্তরটা হলো — Live Server শুধু স্ট্যাটিক HTML ফাইল দেখানোর জন্য বানানো, এটা দিয়ে তুমি কোনো লজিক চালাতে পারবে না (যেমন "যদি ইউজার লগইন করা থাকে, তাহলে প্রোফাইল দেখাও, নাহলে লগইন পেজ দেখাও")। প্রকৃত ব্যাকএন্ড ডেভেলপমেন্টে আমাদের এমন একটা সার্ভার দরকার যেটার উপর আমাদের সম্পূর্ণ নিয়ন্ত্রণ থাকবে — কে কী পাবে, কখন পাবে, কীভাবে পাবে। সেই নিয়ন্ত্রণ পাওয়ার প্রথম ধাপ হলো নিজে হাতে একটা সার্ভার বানিয়ে দেখা, এমনকি সেটা যত সাধারণই হোক না কেন।

Node.js-এর মধ্যেই একটা বিল্ট-ইন মডিউল আছে, নাম `http`, যেটা দিয়ে আমরা সরাসরি একটা ওয়েব সার্ভার বানাতে পারি — কোনো বাড়তি লাইব্রেরি ইনস্টল না করেই। চলো লিখে ফেলি।

একটা ফোল্ডার বানাও, তার ভেতরে `server.js` নামে একটা ফাইল তৈরি করো, লেখো:

```js
const http = require('http');

const server = http.createServer((request, response) => {
  response.end('হ্যালো, এটা আমার নিজের বানানো সার্ভার থেকে জবাব!');
});

server.listen(3000, () => {
  console.log('সার্ভার চালু আছে port 3000-এ');
});
```

টার্মিনালে গিয়ে চালাও:

```bash
node server.js
```

টার্মিনালে "সার্ভার চালু আছে port 3000-এ" লেখাটা দেখতে পাবে, আর প্রোগ্রামটা থেমে থাকবে না, চলতেই থাকবে — এটাই স্বাভাবিক, কারণ সার্ভারকে তো সবসময় "শুনতে" (listen) হবে, একবার কাজ করে বন্ধ হয়ে গেলে চলবে না।

এখন ব্রাউজারে যাও, ঠিকানার বারে লেখো `http://localhost:3000`, এন্টার চাপো। দেখবে স্ক্রিনে লেখা এসেছে "হ্যালো, এটা আমার নিজের বানানো সার্ভার থেকে জবাব!"

এই কয়েক লাইন কোডে ঠিক কী ঘটলো, এবার লাইন ধরে বুঝি:

```js
const http = require('http');
```
এই লাইনটা Node.js-এর বিল্ট-ইন `http` মডিউলটা আমাদের ফাইলে নিয়ে আসছে। `require` হলো Node.js-এর একটা পদ্ধতি, যেটা দিয়ে বাইরের (বা বিল্ট-ইন) কোড নিজের ফাইলে ব্যবহার করা যায়।

```js
const server = http.createServer((request, response) => {
  response.end('...');
});
```
`http.createServer()` একটা সার্ভার তৈরি করে। এর ভেতরে যে ফাংশনটা দিয়েছি (`(request, response) => {...}`), সেটা একটা বিশেষ ফাংশন — এটা **প্রতিবার একটা নতুন request আসলে** স্বয়ংক্রিয়ভাবে চলে। এই ফাংশনের দুটো প্যারামিটার — `request` (ব্রাউজার কী পাঠিয়েছে, সেই তথ্য) এবং `response` (আমরা কী ফেরত পাঠাবো, সেটা তৈরি করার হাতিয়ার)। `response.end(...)` দিয়ে আমরা বলে দিচ্ছি — "এই টেক্সটটাই জবাব, আর জবাব শেষ, পাঠিয়ে দাও।"

```js
server.listen(3000, () => {
  console.log('...');
});
```
`server.listen(3000, ...)` সার্ভারটাকে বলছে — "৩০০০ নম্বর পোর্টে কান পেতে বসে থাকো, কেউ অনুরোধ পাঠালেই সাড়া দাও।" দ্বিতীয় প্যারামিটারের ফাংশনটা শুধু একবার চলে, যখন সার্ভার সফলভাবে চালু হয় — এটা মূলত একটা নিশ্চিতকরণ বার্তা দেখানোর জন্য।

এখানে একটা জিনিস লক্ষ্য করার মতো — এই সার্ভারটা তুমি যাই রিকোয়েস্ট করো না কেন (`/`, `/about`, `/kichu-ekta`), সবসময় একই জবাব দেবে, কারণ আমরা এখনো `request`-এর ভেতরের তথ্য (যেমন কোন পাতা চাওয়া হয়েছে) পরীক্ষা করছি না। এটাই এই মুহূর্তে আমাদের সার্ভারের সবচেয়ে বড় সীমাবদ্ধতা, আর ঠিক এই সীমাবদ্ধতা কাটিয়ে ওঠার কাজটাই আমরা করবো এই মডিউলের পরের কয়েকটা লেসনে।

সার্ভার বন্ধ করার জন্য টার্মিনালে চাপো `Ctrl + C`।

তুমি হয়তো এখন ভাবছো — Live Server আর এই আমাদের নিজের বানানো সার্ভারের মধ্যে পার্থক্য কী, দুটোই তো localhost-এ কিছু একটা দেখাচ্ছে। উত্তর হলো — Live Server একটা রেডিমেড টুল, যেটার ভেতরের কোড অন্য কেউ লিখে রেখেছে, তুমি শুধু ব্যবহার করছো। কিন্তু এই `server.js`-এর প্রতিটা লাইন তুমি নিজে লিখেছো, তুমি জানো ভেতরে ঠিক কী ঘটছে, আর তাই তুমি এখন এটাকে যেভাবে খুশি বদলাতে, বাড়াতে পারবে। এই "সম্পূর্ণ নিয়ন্ত্রণ"-টাই ব্যাকএন্ড ডেভেলপমেন্টের মূল ভিত্তি।
