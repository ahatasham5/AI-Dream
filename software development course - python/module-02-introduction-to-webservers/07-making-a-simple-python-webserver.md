# ০৭. Making a Simple Python Webserver

এতক্ষণ আমরা যা দেখেছি সেটা সবই তত্ত্ব আর পর্যবেক্ষণ ছিলো — Live Server নামের একটা রেডি টুল ব্যবহার করে দেখেছি সার্ভার কীভাবে আচরণ করে। এবার সময় এসেছে সেই একই আচরণ, নিজের হাতে, কোনো রেডিমেড টুল ছাড়াই তৈরি করার।

কেন নিজে বানানো দরকার, যেখানে Live Server-এর মতো টুল তো আছেই? উত্তরটা হলো — Live Server শুধু স্ট্যাটিক HTML ফাইল দেখানোর জন্য বানানো, এটা দিয়ে তুমি কোনো লজিক চালাতে পারবে না (যেমন "যদি ইউজার লগইন করা থাকে, তাহলে প্রোফাইল দেখাও, নাহলে লগইন পেজ দেখাও")। প্রকৃত ব্যাকএন্ড ডেভেলপমেন্টে আমাদের এমন একটা সার্ভার দরকার যেটার উপর আমাদের সম্পূর্ণ নিয়ন্ত্রণ থাকবে — কে কী পাবে, কখন পাবে, কীভাবে পাবে। সেই নিয়ন্ত্রণ পাওয়ার প্রথম ধাপ হলো নিজে হাতে একটা সার্ভার বানিয়ে দেখা, এমনকি সেটা যত সাধারণই হোক না কেন।

Python-এর মধ্যেই একটা বিল্ট-ইন মডিউল আছে, নাম `http.server`, যেটা দিয়ে আমরা সরাসরি একটা ওয়েব সার্ভার বানাতে পারি — কোনো বাড়তি লাইব্রেরি ইনস্টল না করেই। চলো লিখে ফেলি।

একটা ফোল্ডার বানাও, তার ভেতরে `server.py` নামে একটা ফাইল তৈরি করো, লেখো:

```python
from http.server import BaseHTTPRequestHandler, HTTPServer

class MyHandler(BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(200)
        self.end_headers()
        self.wfile.write("হ্যালো, এটা আমার নিজের বানানো সার্ভার থেকে জবাব!".encode("utf-8"))

server = HTTPServer(("localhost", 3000), MyHandler)
print("সার্ভার চালু আছে port 3000-এ")
server.serve_forever()
```

টার্মিনালে গিয়ে চালাও:

```bash
python server.py
```

টার্মিনালে "সার্ভার চালু আছে port 3000-এ" লেখাটা দেখতে পাবে, আর প্রোগ্রামটা থেমে থাকবে না, চলতেই থাকবে — এটাই স্বাভাবিক, কারণ সার্ভারকে তো সবসময় "শুনতে" (listen) হবে, একবার কাজ করে বন্ধ হয়ে গেলে চলবে না।

এখন ব্রাউজারে যাও, ঠিকানার বারে লেখো `http://localhost:3000`, এন্টার চাপো। দেখবে স্ক্রিনে লেখা এসেছে "হ্যালো, এটা আমার নিজের বানানো সার্ভার থেকে জবাব!"

এই কয়েক লাইন কোডে ঠিক কী ঘটলো, এবার লাইন ধরে বুঝি:

```python
from http.server import BaseHTTPRequestHandler, HTTPServer
```
এই লাইনটা Python-এর বিল্ট-ইন `http.server` মডিউল থেকে দুটো জিনিস আমাদের ফাইলে নিয়ে আসছে। `import` হলো Python-এর একটা পদ্ধতি, যেটা দিয়ে বাইরের (বা বিল্ট-ইন) কোড নিজের ফাইলে ব্যবহার করা যায়।

```python
class MyHandler(BaseHTTPRequestHandler):
    def do_GET(self):
        ...
```
`BaseHTTPRequestHandler` থেকে একটা নতুন ক্লাস বানানো হচ্ছে (`MyHandler`), যেটা বলে দেয় — কোনো request আসলে ঠিক কী করতে হবে। `do_GET` নামের মেথডটা **প্রতিবার একটা নতুন GET request আসলে** স্বয়ংক্রিয়ভাবে চলে। এর ভেতরে `self` দিয়ে আমরা রেসপন্স তৈরি করার হাতিয়ারগুলো ব্যবহার করতে পারি।

```python
self.send_response(200)
self.end_headers()
self.wfile.write("...".encode("utf-8"))
```
`send_response(200)` মানে "সব ঠিক আছে, একটা জবাব পাঠাচ্ছি।" `end_headers()` বলে দেয় হেডার লেখা শেষ, এখন আসল কনটেন্ট আসবে। `self.wfile.write(...)` দিয়ে আমরা প্রকৃত জবাব-টেক্সট পাঠাই — এখানে `.encode("utf-8")` লাগে কারণ `wfile.write()` টেক্সট না, বাইট (bytes) আশা করে।

```python
server = HTTPServer(("localhost", 3000), MyHandler)
server.serve_forever()
```
`HTTPServer(...)` সার্ভারটা তৈরি করে — প্রথম প্যারামিটারে (হোস্ট, পোর্ট) জোড়া, দ্বিতীয়টায় বলে দিচ্ছি কোন হ্যান্ডলার ক্লাস ব্যবহার হবে। `server.serve_forever()` সার্ভারটাকে বলছে — "৩০০০ নম্বর পোর্টে কান পেতে বসে থাকো, কেউ অনুরোধ পাঠালেই সাড়া দাও, আর এই কাজ চলতেই থাকবে।"

এখানে একটা জিনিস লক্ষ্য করার মতো — এই সার্ভারটা তুমি যাই রিকোয়েস্ট করো না কেন (`/`, `/about`, `/kichu-ekta`), সবসময় একই জবাব দেবে, কারণ আমরা এখনো request-এর ভেতরের তথ্য (যেমন কোন পাতা চাওয়া হয়েছে, `self.path`-এ থাকে) পরীক্ষা করছি না। এটাই এই মুহূর্তে আমাদের সার্ভারের সবচেয়ে বড় সীমাবদ্ধতা, আর ঠিক এই সীমাবদ্ধতা কাটিয়ে ওঠার কাজটাই আমরা করবো এই মডিউলের পরের কয়েকটা লেসনে।

সার্ভার বন্ধ করার জন্য টার্মিনালে চাপো `Ctrl + C`।

> **এক লাইনের শর্টকাট:** যদি শুধু একটা ফোল্ডারের স্ট্যাটিক ফাইলগুলো দ্রুত সার্ভ করতে চাও, কোনো কোড না লিখেই, টার্মিনালে সেই ফোল্ডারে গিয়ে চালাতে পারো `python -m http.server 3000` — এটা সেই ফোল্ডারের ফাইলগুলো সরাসরি সার্ভ করে দেবে। কিন্তু এখানে আমরা ইচ্ছাকৃতভাবে `BaseHTTPRequestHandler` দিয়ে হাতে লিখলাম, কারণ আমাদের লক্ষ্য শুধু ফাইল সার্ভ করা না, ভবিতে নিজের লজিক যুক্ত করার ক্ষমতা বোঝা।

তুমি হয়তো এখন ভাবছো — Live Server আর এই আমাদের নিজের বানানো সার্ভারের মধ্যে পার্থক্য কী, দুটোই তো localhost-এ কিছু একটা দেখাচ্ছে। উত্তর হলো — Live Server একটা রেডিমেড টুল, যেটার ভেতরের কোড অন্য কেউ লিখে রেখেছে, তুমি শুধু ব্যবহার করছো। কিন্তু এই `server.py`-এর প্রতিটা লাইন তুমি নিজে লিখেছো, তুমি জানো ভেতরে ঠিক কী ঘটছে, আর তাই তুমি এখন এটাকে যেভাবে খুশি বদলাতে, বাড়াতে পারবে। এই "সম্পূর্ণ নিয়ন্ত্রণ"-টাই ব্যাকএন্ড ডেভেলপমেন্টের মূল ভিত্তি।
