# ২০. Mutex and RWMutex in Go

লেসন ০৭-এ আমরা দেখেছিলাম গোরুটিন কতটা সহজে বানানো যায় — শুধু `go` কীওয়ার্ড বসিয়ে দিলেই একটা নতুন কাজ সমান্তরালে চলতে শুরু করে। কিন্তু এই স্বাধীনতারই একটা বিপজ্জনক দিক আছে। কল্পনা করো একটা ব্যাংকের কাউন্টার, যেখানে দুইজন কর্মচারী একই খাতায় একই সাথে টাকা যোগ করছে — একজন দেখলো ব্যালেন্স ১০০, নিজের হিসাবে ৫০ যোগ করে লিখলো ১৫০; ঠিক তখনই আরেকজনও ব্যালেন্স ১০০ দেখে নিজের ৩০ যোগ করে লিখলো ১৩০। আসল ফলাফল হওয়ার কথা ছিলো ১৮০, কিন্তু খাতায় থেকে গেলো ১৩০ বা ১৫০ — যেটা শেষে লেখা হলো সেটাই টিকলো। এই ঘটনাটাকেই বলে **race condition**।

গোরুটিনগুলো যখন একই মেমরি (যেমন একটা ভ্যারিয়েবল বা ম্যাপ) শেয়ার করে পড়ে এবং লেখে, তখন এই সমস্যা দেখা দিতে পারে। সমাধান হলো — একবারে শুধু একজনকেই "খাতাটা" ধরতে দেওয়া, বাকিদের অপেক্ষা করানো। এই কাজটাই করে **sync.Mutex** (mutual exclusion)।

```go
package main

import (
	"fmt"
	"sync"
)

type SafeCounter struct {
	mu    sync.Mutex
	count int
}

func (c *SafeCounter) Increment() {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.count++
}

func main() {
	counter := SafeCounter{}
	var wg sync.WaitGroup

	for i := 0; i < 1000; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			counter.Increment()
		}()
	}
	wg.Wait()
	fmt.Println("Final count:", counter.count) // সবসময় 1000
}
```

`mu.Lock()` কল করার মানে হলো "আমি এই অংশটা ব্যবহার করছি, আর কেউ ঢুকতে পারবে না।" `mu.Unlock()` কল করলে সেই তালা খুলে যায়, পরের গোরুটিন ঢুকতে পারে। `defer c.mu.Unlock()` ব্যবহার করা ভালো অভ্যাস — ফাংশনের ভেতরে যতগুলো রিটার্ন পথই থাকুক না কেন, Unlock নিশ্চিতভাবে কল হবে। (`wg` আর `WaitGroup` নিয়ে বিস্তারিত পরের লেসনে আসছে।)

কিন্তু Mutex-এর একটা সীমাবদ্ধতা আছে — এটা **read আর write দুটোকেই** সমানভাবে ব্লক করে, এমনকি যখন একাধিক গোরুটিন শুধু ডেটা **পড়তেই** চায়, লিখতে চায় না। ধরো একটা ক্যাশ বা কনফিগারেশন, যেটা মিনিটে একবার আপডেট হয় কিন্তু সেকেন্ডে হাজারবার পড়া হয় — এখানে সব রিডারকে একে একে সিরিয়ালি পড়তে বাধ্য করা অপচয়। এই পরিস্থিতির জন্য আছে **sync.RWMutex**, যেটা একসাথে একাধিক রিডারকে অনুমতি দেয় (`RLock`/`RUnlock`), কিন্তু কেউ লিখতে চাইলে (`Lock`/`Unlock`) সবাইকে থামিয়ে দেয়।

```go
type Config struct {
	mu   sync.RWMutex
	data map[string]string
}

func (c *Config) Get(key string) string {
	c.mu.RLock()
	defer c.mu.RUnlock()
	return c.data[key]
}

func (c *Config) Set(key, value string) {
	c.mu.Lock()
	defer c.mu.Unlock()
	c.data[key] = value
}
```

সহজ নিয়ম — write কম, read বেশি হলে RWMutex বেছে নাও; দুটোই কাছাকাছি পরিমাণে হলে সাধারণ Mutex-ই যথেষ্ট এবং সরল। এখন প্রশ্ন হলো, একটা প্রোগ্রামের মেইন ফাংশন কীভাবে জানবে যে সবগুলো গোরুটিন তাদের কাজ শেষ করেছে — এই সমন্বয়ের কাজটাই দেখবো পরের লেসনে, **sync.WaitGroup** দিয়ে।
