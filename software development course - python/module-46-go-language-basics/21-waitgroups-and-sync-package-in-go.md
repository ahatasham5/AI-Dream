# ২১. WaitGroups and Sync Package in Go

আগের লেসনে আমরা একটা কোড স্নিপেটে `sync.WaitGroup` ব্যবহার করে ফেলেছিলাম, কিন্তু ব্যাখ্যাটা বাকি রেখেছিলাম — এবার সেটা পুরোপুরি বুঝে নেওয়া যাক। সমস্যাটা এরকম — লেসন ০৭-এ শেখা `go` কীওয়ার্ড দিয়ে তুমি একটা গোরুটিন ছেড়ে দিলে, কিন্তু মেইন ফাংশন সেটার জন্য অপেক্ষা করে না। মেইন ফাংশন শেষ হয়ে গেলে পুরো প্রোগ্রামই বন্ধ হয়ে যায়, তখন গোরুটিন কাজ শেষ করুক বা না করুক, কিছু যায় আসে না। এটা অনেকটা অফিসের বসের মতো, যে কর্মচারীদের কাজ দিয়ে নিজে বাড়ি চলে গেলো — কেউ কাজ শেষ করলো কিনা তার খবর রাখলো না।

এই সমস্যা সমাধানের জন্য দরকার একটা "গণনাকারী" — যে ট্র্যাক রাখবে কতগুলো কাজ চলছে, আর সবগুলো শেষ না হওয়া পর্যন্ত মেইন ফাংশনকে থামিয়ে রাখবে। এই কাজটাই করে **sync.WaitGroup**, তিনটা মেথডের মাধ্যমে — `Add`, `Done`, আর `Wait`।

```go
package main

import (
	"fmt"
	"sync"
)

func downloadFile(id int, wg *sync.WaitGroup) {
	defer wg.Done() // কাজ শেষ হলে গণনা থেকে এক কমিয়ে দাও
	fmt.Printf("file %d: downloading...\n", id)
	fmt.Printf("file %d: done\n", id)
}

func main() {
	var wg sync.WaitGroup

	for i := 1; i <= 5; i++ {
		wg.Add(1) // একটা নতুন কাজ শুরু হচ্ছে, গণনা বাড়াও
		go downloadFile(i, &wg)
	}

	wg.Wait() // গণনা শূন্যে না নামা পর্যন্ত এখানে থেমে থাকো
	fmt.Println("সব ফাইল ডাউনলোড সম্পন্ন")
}
```

প্রতিটা `Add(1)` কল বলছে "একটা নতুন কাজ যোগ হলো", প্রতিটা `Done()` বলছে "একটা কাজ শেষ হলো" (এটা `Add(-1)`-এর সমতুল্য)। `Wait()` ব্লক করে থাকে যতক্ষণ না গণনাটা শূন্যে নামে। খেয়াল করো, `wg` পাঠানো হয়েছে **পয়েন্টার** হিসেবে (`&wg`) — কারণ WaitGroup-কে কপি করলে প্রতিটা গোরুটিন নিজের আলাদা কপির উপর কাজ করবে, আর গণনাটা মেইন ফাংশনের সাথে সমন্বিত থাকবে না।

এখানে Mutex আর WaitGroup-এর কাজের পার্থক্যটা স্পষ্ট করে নেওয়া দরকার — Mutex রক্ষা করে **শেয়ার্ড ডেটা**কে, একই সময়ে একাধিক গোরুটিন যাতে ঝামেলা না করে; WaitGroup ট্র্যাক রাখে **কাজের অগ্রগতি**কে, কে কখন শেষ করলো তার হিসাব। দুটো প্রায়ই একসাথে ব্যবহৃত হয় — যেমন লেসন ২০-এর `SafeCounter` উদাহরণে আমরা `wg` আর `mu` দুটোই একসাথে ব্যবহার করেছিলাম।

sync প্যাকেজে আরেকটা ছোট কিন্তু কার্যকর টুল আছে — **sync.Once**, যেটা নিশ্চিত করে একটা নির্দিষ্ট কোড ব্লক পুরো প্রোগ্রামের জীবদ্দশায় ঠিক **একবারই** চলবে, যতগুলো গোরুটিন থেকেই চেষ্টা করা হোক না কেন। এটা কাজে লাগে যেমন ডেটাবেজ কানেকশন ইনিশিয়ালাইজ করা বা কনফিগারেশন একবার লোড করার ক্ষেত্রে।

```go
var once sync.Once

func setupDatabase() {
	once.Do(func() {
		fmt.Println("ডেটাবেজ কানেকশন তৈরি হচ্ছে...")
	})
}
```

যতবারই `setupDatabase()` কল করা হোক, ভেতরের ফাংশনটা মাত্র একবারই এক্সিকিউট হবে। এখন আমরা গোরুটিন, মিউটেক্স আর ওয়েটগ্রুপ — তিনটাকেই চিনি; পরের লেসনে এই সবকিছু একসাথে মিলিয়ে বানাবো একটা বাস্তব প্যাটার্ন — **worker pool**, যা দিয়ে বহু সংখ্যক কাজ নিয়ন্ত্রিতভাবে সামলানো যায়।
