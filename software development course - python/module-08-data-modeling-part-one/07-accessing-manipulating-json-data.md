# ০৭. Accessing and Manipulating JSON Data

একটা JSON object হাতে পাওয়া মানেই কাজ শেষ না — বরং আসল কাজ শুরু হয় তখন, যখন তোমাকে তার ভেতর থেকে নির্দিষ্ট তথ্য খুঁজে বের করতে হয়, অথবা কোনো একটা মান পরিবর্তন করতে হয়। ধরো একটা আলমারি আছে, যার ভেতরে অনেকগুলো ড্রয়ার, আর প্রতিটা ড্রয়ারের ভেতরে আবার ছোট ছোট বাক্স থাকতে পারে। JSON object-এর ভেতরের ডেটা অ্যাক্সেস করা অনেকটা এই আলমারি থেকে সঠিক ড্রয়ার খুলে সঠিক বাক্সটা বের করার মতোই একটা সুশৃঙ্খল প্রক্রিয়া।

ধরা যাক আমাদের কাছে আগের লেসনের প্রোডাক্ট dict-টা আছে:

```python
product = {
    "id": "prod_1001",
    "title": "রানিং শু",
    "price": 1500,
    "stock": 20,
    "category": "footwear",
    "supplier": {
        "name": "স্পোর্টস হাউস",
        "location": "ঢাকা"
    }
}
```

Python-এ dict-এর ভেতরের মান অ্যাক্সেস করার মূল উপায়টা হলো **bracket notation** (`[]`), তবে এর পাশাপাশি একটা নিরাপদ বিকল্প আছে — **`.get()`** মেথড।

```python
# Bracket notation — key নিশ্চিতভাবে আছে জানা থাকলে
print(product["title"])  # "রানিং শু"
print(product["supplier"]["name"])  # "স্পোর্টস হাউস" — nested dict-এর ভেতরে যাওয়া

# key একটা variable-এ থাকলেও bracket notation একইভাবে কাজ করে
field = "price"
print(product[field])  # 1500

# .get() — key না থাকলে এরর না দিয়ে None (বা একটা default value) ফেরত দেয়
print(product.get("category"))  # "footwear"
print(product.get("discount"))  # None — key নেই, কিন্তু প্রোগ্রাম ক্র্যাশ করলো না
print(product.get("discount", 0))  # 0 — দ্বিতীয় প্যারামিটার হলো default value
```

লক্ষ্য করো, `product["discount"]` লিখলে Python একটা `KeyError` এক্সসেপশন তুলে পুরো প্রোগ্রাম থামিয়ে দিতো (যদি হ্যান্ডল না করা হয়), কারণ `discount` নামের key dict-টাতে নেই। কিন্তু `.get()` ব্যবহার করলে সেটা নিরাপদে `None` ফেরত দেয়, প্রোগ্রাম চলতে থাকে।

**একটা সাধারণ কিন্তু বিপজ্জনক ভুল** হলো — সবজায়গায় ভাবনাহীনভাবে `.get()` ব্যবহার করা, আর `KeyError`-কে "বিরক্তিকর" ভেবে এড়িয়ে যাওয়া। বাস্তবে `KeyError` অনেক সময় একটা দরকারি সংকেত — যদি `title` ফিল্ডটা সত্যিই থাকা *আবশ্যিক* হয় (প্রতিটা প্রোডাক্টের নাম থাকতেই হবে), আর কোনো bug-এর কারণে সেটা অনুপস্থিত থাকে, তাহলে `product.get("title")` চুপচাপ `None` ফেরত দিয়ে দিবে, আর পরের কোডে সেই `None`-টা আরও দূরে গিয়ে অন্য কোনো অদ্ভুত এররের জন্ম দিবে — যেখানে সমস্যার আসল কারণ খুঁজে বের করা কঠিন হয়ে যাবে। তাই নিয়মটা এমন — **আবশ্যিক ফিল্ডের জন্য bracket notation ব্যবহার করো** (যাতে সমস্যা হলেই সাথে সাথে স্পষ্ট এরর পাওয়া যায়), আর **ঐচ্ছিক ফিল্ডের জন্য `.get()` ব্যবহার করো** (একটা যুক্তিসঙ্গত default value দিয়ে)।

এবার আসা যাক পরিবর্তনের (manipulation) প্রসঙ্গে। এখানে একটা গুরুত্বপূর্ণ পার্থক্য বোঝা দরকার — **mutable** (সরাসরি পরিবর্তন) বনাম **immutable** (মূল object অক্ষত রেখে নতুন object তৈরি) পদ্ধতি।

```python
# Mutable পদ্ধতি — সরাসরি মূল dict পরিবর্তন করা হচ্ছে
product["stock"] = 15
product["price"] = 1400
print(product["stock"])  # 15 — মূল dict-ই বদলে গেছে

# Immutable পদ্ধতি — dict unpacking (**) ব্যবহার করে একটা নতুন dict তৈরি করা হচ্ছে
updated_product = {**product, "stock": 15, "price": 1400}
print(product["stock"])  # এখনও পুরনো মান, কারণ মূল dict অক্ষত আছে
print(updated_product["stock"])  # 15 — নতুন dict-এ পরিবর্তিত মান
```

`{**product, "stock": 15}`-এ ব্যবহৃত দুইটা তারকা (`**`) কে বলে **dict unpacking** — এটা মূল dict-এর সব key-value কপি করে একটা নতুন dict তৈরি করে, তারপর যে key-গুলো নতুন করে দেওয়া হয়েছে (এখানে `stock`), সেগুলো ওভাররাইট করে দেয়। JavaScript-এ যেটাকে spread operator (`...`) বলা হতো, Python dict-এর জন্য এই `**` অপারেটরটাই ঠিক সেই কাজ করে।

প্রশ্ন হতে পারে — mutable পদ্ধতি সহজ হলেও কেন immutable পদ্ধতি এত গুরুত্বপূর্ণ, বিশেষ করে ব্যাকএন্ডে? কারণটা হলো নির্ভরযোগ্যতা। ধরো একটা ফাংশন ডেটাবেজ থেকে একটা প্রোডাক্ট object নিয়ে এলো, আর সেটা নিয়ে কয়েকটা হিসাব-নিকাশ করতে হবে বিভিন্ন জায়গায়। যদি কোনো একটা ফাংশন সরাসরি সেই মূল object পরিবর্তন করে ফেলে, তাহলে অন্য জায়গায় যেখানে পুরনো মানটা দরকার ছিল, সেখানে ভুল ফলাফল আসবে — কারণ ডেটা "চুপিচুপি" বদলে গেছে। immutable পদ্ধতি এই সমস্যা এড়ায়, কারণ প্রতিটা পরিবর্তন একটা নতুন, আলাদা object তৈরি করে, মূলটা অক্ষত থাকে।

nested object-এর ক্ষেত্রেও একই নীতি প্রযোজ্য, শুধু একটু বাড়তি যত্ন লাগে:

```python
# supplier-এর location পরিবর্তন করতে হলে nested unpacking দরকার
relocated = {
    **product,
    "supplier": {**product["supplier"], "location": "চট্টগ্রাম"}
}
print(relocated["supplier"]["location"])  # "চট্টগ্রাম"
print(product["supplier"]["location"])  # "ঢাকা" — মূল ডেটা অক্ষত
```

এই bracket notation/`.get()` আর mutable/immutable পরিবর্তনের কৌশলগুলো প্রতিটা ব্যাকএন্ড route handler-এ বারবার ব্যবহার হবে — বিশেষ করে PUT আর PATCH endpoint-এ, যেখানে কোনো একটা রিসোর্সের নির্দিষ্ট কিছু ফিল্ড আপডেট করতে হয়। কিন্তু বাস্তব ডেটা সবসময় একটা একক dict না — বেশিরভাগ ক্ষেত্রেই আমাদের কাজ করতে হয় dict-এর একটা তালিকা নিয়ে, যেমন সব প্রোডাক্টের list। পরের লেসনে আমরা দেখবো কীভাবে সেই list-গুলো নিয়ে কার্যকরভাবে কাজ করা যায়।
