# ০৩. Introduction to JSON — why, how and when?

কল্পনা করো তুমি একটা আন্তর্জাতিক কার্গো কোম্পানির মালিক। তোমার জাহাজে বিভিন্ন দেশ থেকে বিভিন্ন ধরনের মালামাল আসে — কেউ পাঠায় বাক্সে, কেউ বস্তায়, কেউ খোলা অবস্থায়। প্রতিবার নতুন প্যাকেজিং দেখে বুঝতে হয় এর ভেতরে কী আছে, কীভাবে খুলতে হয় — এটা ভীষণ অদক্ষ একটা ব্যবস্থা। এই সমস্যার সমাধানে শিপিং ইন্ডাস্ট্রি একটা জিনিস আবিষ্কার করেছিল — **স্ট্যান্ডার্ড কন্টেইনার**। এখন যেকোনো দেশ থেকে যেকোনো মালামাল একই আকৃতির কন্টেইনারে ভরে পাঠানো যায়, আর পৃথিবীর যেকোনো বন্দরের ক্রেন সেটা তুলতে-নামাতে জানে, কারণ কন্টেইনারের গঠনটা সবার কাছেই পরিচিত।

সফটওয়্যার জগতেও ঠিক এই একই সমস্যা ছিল। একটা সিস্টেম হয়তো JavaScript-এ লেখা, আরেকটা Python-এ, আরেকটা Java-তে — কিন্তু তাদের একে অপরের সাথে ডেটা আদান-প্রদান করতে হয়। যদি প্রতিটা ভাষা তার নিজস্ব পদ্ধতিতে ডেটা সাজায়, তাহলে একটা সিস্টেমের ডেটা আরেকটা সিস্টেম বুঝতেই পারবে না। এই সমস্যার সমাধান হিসেবে এসেছে **JSON (JavaScript Object Notation)** — ডেটা প্যাকেজিং-এর একটা সার্বজনীন "স্ট্যান্ডার্ড কন্টেইনার" ফরম্যাট। নাম JavaScript-এর হলেও, আজকে প্রায় প্রতিটা প্রোগ্রামিং ভাষা JSON পড়তে আর লিখতে পারে।

JSON-এর গঠনটা আসলে আমাদের চেনা — Module 4-এ শেখা Python dict আর list-এর গঠনের সাথে প্রায় হুবহু মিল। একটা সাধারণ JSON দেখা যাক:

```json
{
  "name": "রহিম",
  "age": 25,
  "isLoggedIn": true,
  "hobbies": ["ক্রিকেট", "বই পড়া"],
  "address": {
    "city": "ঢাকা",
    "zip": "1200"
  }
}
```

লক্ষ্য করো — key-value জোড়া (`"name": "রহিম"`), array (`hobbies`), এমনকি nested object (`address`) — সবকিছুই এখানে আছে। এই জন্যই JSON-কে বলা হয় ডেটা আদান-প্রদানের **lingua franca** বা সার্বজনীন ভাষা — এটা এতটাই সহজবোধ্য আর নমনীয় যে জটিল থেকে জটিল ডেটাও এভাবে সাজানো যায়, আবার যেকোনো সিস্টেম সেটা পড়তে পারে।

কিন্তু এখানে একটা সূক্ষ্ম কিন্তু গুরুত্বপূর্ণ পার্থক্য বোঝা দরকার — JSON আর Python dict একই জিনিস না। JSON হলো একটা **টেক্সট ফরম্যাট** — মানে এটা আসলে একটা স্ট্রিং, যেটা নেটওয়ার্কের মধ্য দিয়ে পাঠানো যায়, ফাইলে সংরক্ষণ করা যায়। অন্যদিকে Python dict হলো মেমোরিতে থাকা একটা লাইভ ডেটা স্ট্রাকচার, যেটার উপর তুমি সরাসরি কাজ করতে পারো। এই দুইয়ের মধ্যে রূপান্তর করার জন্য Python-এর বিল্ট-ইন `json` মডিউলে দুইটা মূল ফাংশন আছে:

```python
import json

user = {
    "name": "রহিম",
    "age": 25
}

# Python dict থেকে JSON স্ট্রিং বানানো — যখন নেটওয়ার্কে পাঠাতে হবে
json_string = json.dumps(user)
print(json_string)
# আউটপুট: '{"name": "রহিম", "age": 25}'
print(type(json_string))  # <class 'str'>

# JSON স্ট্রিং থেকে আবার Python dict বানানো — যখন ডেটা গ্রহণ করা হবে
parsed_back = json.loads(json_string)
print(parsed_back["name"])  # রহিম
print(type(parsed_back))  # <class 'dict'>
```

`json.dumps()`-কে ভাবতে পারো মালামালকে কন্টেইনারে ভরার কাজ হিসেবে — পাঠানোর জন্য প্রস্তুত করা (dumps = "dump string")। আর `json.loads()` হলো বন্দরে কন্টেইনার খুলে ভেতরের মালামাল বের করার কাজ — গ্রহণকারী পাশে সেটা ব্যবহারযোগ্য dict-এ রূপান্তর করা (loads = "load string")।

FastAPI-তে কাজ করার সময় বাস্তবে তুমি প্রায়ই `json.dumps`/`json.loads` সরাসরি লিখবে না, কারণ **Pydantic model** এই কাজটা নিজে থেকেই করে দেয় — একটা রিকোয়েস্ট বডি এলে Pydantic সেটা অটোমেটিক dict/object-এ পার্স করে, আর রেসপন্স পাঠানোর সময় সেই model-কে অটোমেটিক JSON-এ রূপান্তর করে দেয়। কিন্তু এর ভেতরে ঠিক কী ঘটছে বোঝার জন্য `json` মডিউলের এই মৌলিক আচরণটা জানা জরুরি।

এখন প্রশ্ন আসতে পারে — এই "কন্টেইনার খোলা-বন্ধ করার" কাজটা ঠিক কখন হয়? উত্তরটা হলো — প্রায় প্রতিবার, যখনই frontend আর backend-এর মধ্যে ডেটা চলাচল করে। Module 6-এ যখন আমরা POST endpoint বানিয়েছিলাম, তখন রিকোয়েস্ট বডিতে যে ডেটা পেয়েছিলাম, সেটা FastAPI ইতিমধ্যে JSON থেকে Pydantic model/dict-এ পার্স করে দিয়েছিল আমাদের হয়ে। পরের লেসনে আমরা ঠিক এই যাত্রাটা — frontend থেকে backend পর্যন্ত JSON-এর সম্পূর্ণ পথ — ধাপে ধাপে অনুসরণ করবো।
