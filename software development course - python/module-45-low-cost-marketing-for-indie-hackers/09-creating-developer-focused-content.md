# ০৯. Creating Developer-focused Content

আমরা এতদিন সাধারণভাবে কনটেন্ট মার্কেটিং, ব্লগিং, আর Twitter/X নিয়ে কথা বলেছি। এই লেসনে আমরা একটু নির্দিষ্ট হবো — যখন তোমার persona নিজেই একজন ডেভেলপার (যেমন একটা API প্রোডাক্ট, একটা ডেভেলপার টুল, বা লাইব্রেরি বানাচ্ছো), তখন কনটেন্ট স্ট্র্যাটেজি সাধারণ B2C মার্কেটিং থেকে আলাদা হয়ে যায়।

ডেভেলপাররা সাধারণ গ্রাহকদের চেয়ে বেশ ভিন্নভাবে কেনাকাটার সিদ্ধান্ত নেয় — তারা বিপণনী ভাষায় (marketing speak) সহজে প্রভাবিত হয় না, বরং টেকনিক্যাল প্রমাণ চায়। "সবচেয়ে দ্রুত API!" বলার চেয়ে "আমাদের বেঞ্চমার্ক দেখাচ্ছে ৫০ms p99 latency, এই সেটআপে এই মেথডলজি দিয়ে মাপা" — এই দ্বিতীয় ধরনের দাবি ডেভেলপারদের কাছে অনেক বেশি বিশ্বাসযোগ্য, কারণ এটা যাচাইযোগ্য।

```mermaid
flowchart LR
    A[সাধারণ মার্কেটিং ভাষা] -->|"সেরা", "দ্রুততম"| B[ডেভেলপাররা সন্দিহান হয়]
    C[প্রমাণ-ভিত্তিক কনটেন্ট] -->|বেঞ্চমার্ক, কোড, ওপেন সোর্স| D[ডেভেলপাররা বিশ্বাস করে]
```

ডেভেলপার-কেন্দ্রিক কনটেন্টের সবচেয়ে কার্যকর ফরম্যাটগুলোর একটা হলো **ডকুমেন্টেশন-কে-মার্কেটিং হিসেবে ব্যবহার করা**। একটা প্রোডাক্টের ডকুমেন্টেশন যদি পরিষ্কার, উদাহরণসহ, আর দ্রুত শুরু করার মতো (quick-start guide) হয়, এটা নিজেই একটা মার্কেটিং টুল — কারণ ডেভেলপাররা প্রায়ই একটা টুল বেছে নেয়ার আগে তার ডকুমেন্টেশনের মান দেখেই সিদ্ধান্ত নেয়।

```markdown
## Quick Start
এই তিনটা লাইন দিয়ে তুমি প্রথম API কলটা করতে পারবে:

\`\`\`bash
curl -X POST https://api.example.com/v1/invoices \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{"client": "রাফি", "amount": 5000}'
\`\`\`
```

লক্ষ্য করো, এই উদাহরণটা কপি-পেস্ট করেই চালানো যায় — Module 45-এর লেসন ০৭-এ শেখা "রানযোগ্য কোড" নীতির সরাসরি প্রয়োগ, শুধু এবার এটা ডকুমেন্টেশনের প্রেক্ষাপটে।

আরেকটা কার্যকর কৌশল হলো **তুলনামূলক কনটেন্ট** বানানো — "InvoiceBari vs FreshBooks: বাংলাদেশি ফ্রিল্যান্সারদের জন্য কোনটা ভালো" এই ধরনের পোস্ট, যা Module 43-এর লেসন ০২-তে শেখা কম্পিটিটিভ অ্যানালাইসিসের একটা পাবলিক-ফেসিং সংস্করণ। এই ধরনের পোস্ট SEO-তেও ভালো কাজ করে (মানুষ প্রায়ই "X vs Y" লিখে সার্চ করে) আর সৎভাবে লেখা হলে (নিজের দুর্বলতা স্বীকার করে) বিশ্বাসযোগ্যতা বাড়ায়।

| কনটেন্ট ফরম্যাট | কেন কাজ করে |
|---|---|
| Quick-start ডকুমেন্টেশন | তাৎক্ষণিক মূল্য প্রমাণ করে |
| বেঞ্চমার্ক/পারফরম্যান্স পোস্ট | যাচাইযোগ্য দাবি |
| তুলনামূলক পোস্ট (X vs Y) | সিদ্ধান্ত নেয়ার সাহায্য করে, SEO-বান্ধব |
| ওপেন সোর্স উদাহরণ কোড | সরাসরি ব্যবহারযোগ্য প্রমাণ |

ডেভেলপার-কেন্দ্রিক মার্কেটিং-এর একটা গুরুত্বপূর্ণ নীতি — বিশ্বাসযোগ্যতা তৈরি হয় স্বচ্ছতা থেকে। যদি একটা প্রোডাক্টের সীমাবদ্ধতা থাকে (যেমন এখনো কোনো নির্দিষ্ট ফিচার নেই), সেটা লুকানোর বদলে খোলাখুলি স্বীকার করা ("আমরা এখনো মাল্টি-কারেন্সি সাপোর্ট করি না, এটা রোডম্যাপে আছে") — ডেভেলপার কমিউনিটিতে এই সততা প্রায়ই প্রশংসিত হয়, লুকানোর চেষ্টার চেয়ে।

ডেভেলপার-কেন্দ্রিক কনটেন্টের সবচেয়ে শক্তিশালী রূপ হলো কোড নিজেই পাবলিক করে দেয়া — এটাই আমাদের পরের লেসনের বিষয়, ওপেন সোর্স মার্কেটিং।
