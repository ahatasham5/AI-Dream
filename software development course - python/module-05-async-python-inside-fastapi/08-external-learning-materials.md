# ০৮. Free Related Learning Materials: YouTube

এই মডিউলে আমরা যে বিষয়গুলো নিয়ে কথা বলেছি — GIL, event loop, coroutine, task, Future, race condition, blocking call — এগুলো এমন ধরনের ধারণা, যেগুলো টেক্সট আর কোড দিয়ে যতটা বোঝা যায়, তার চেয়ে অনেক বেশি স্পষ্ট হয়ে যায় যখন সেগুলো **চোখের সামনে অ্যানিমেটেড হয়ে চলতে দেখা যায়**। তাই এই লেসনে আমরা কোনো নতুন কোড শিখবো না, বরং কথা বলবো — এই পর্যায়ে ঠিক কোন ধরনের বাড়তি শেখার উপকরণ খুঁজলে সবচেয়ে বেশি উপকার হবে, আর কেন।

চিন্তা করে দেখো, আমরা এই মডিউলের ৩ আর ৪ নম্বর লেসনে event loop, coroutine, task, আর Future নিয়ে যে ছবিটা এঁকেছিলাম, সেটা একটা স্থির (static) diagram। কিন্তু বাস্তবে এই পুরো প্রক্রিয়াটা সময়ের সাথে বদলাতে থাকে — একটা coroutine শুরু হয়, `await`-এ থামে, event loop অন্য একটাকে চালু করে, আবার ফিরে আসে। এই ধরনের "সময়ের সাথে বদলানো" প্রক্রিয়া বোঝার জন্য সবচেয়ে কার্যকর মাধ্যম হলো **ভিজ্যুয়াল সিমুলেশন** — অর্থাৎ এমন ভিডিও বা টুল, যেখানে প্রতিটা ধাপ একটা একটা করে animate হয়ে দেখানো হয়। ইউটিউবে "Python asyncio event loop explained" বা "Python asyncio visualized" জাতীয় কিছু লিখে খুঁজলে এই ধরনের ভিজ্যুয়াল ব্যাখ্যা পাওয়া যায়, যেগুলো একবার দেখলে এই লেসনগুলোর তত্ত্ব মাথায় আরও শক্তভাবে বসে যাবে।

দ্বিতীয় যে ধরনের কনটেন্ট এই মুহূর্তে সাহায্য করবে, সেটা হলো **PyCon-এর মতো সম্মেলনে asyncio নিয়ে দেওয়া টক**। PyCon (Python-এর সবচেয়ে বড় সম্মেলন, বিভিন্ন দেশে বছরে একাধিকবার হয়) এবং ইউরোপের EuroPython-এর মতো আয়োজনে asyncio-র মূল ডিজাইনার আর অভিজ্ঞ Python কোর ডেভেলপাররা নিজেরাই এসে ব্যাখ্যা করেন ইঞ্জিনটা ভেতরে ভেতরে ঠিক কীভাবে কাজ করে। এই ধরনের আলোচনা এই কোর্সের চেয়ে অনেক গভীরে যায় — GIL কেন এভাবে ডিজাইন হয়েছে, `selectors` module কীভাবে অপারেটিং সিস্টেমের সাথে কথা বলে, এমনকি ভবিষ্যতে GIL সরিয়ে ফেলার (PEP 703-এর মতো প্রস্তাবনা) কী পরিকল্পনা চলছে। এই পর্যায়ে পুরোটা বোঝা না গেলেও সমস্যা নেই — লক্ষ্য হলো একটা পরিচিতি তৈরি করা, যাতে ভবিষ্যতে (বিশেষ করে Process আর Thread নিয়ে আরও গভীরে পড়ার সময়) নামগুলো অপরিচিত না লাগে।

তৃতীয়ত, খুঁজে দেখতে পারো এমন ভিডিও বা ব্লগ যেখানে **FastAPI-এর async ভুল** নিয়ে সরাসরি কথা বলা হয়েছে — বিশেষ করে "blocking the event loop in FastAPI" বা "sync vs async database drivers FastAPI" জাতীয় বিষয়ে। এই মডিউলের পাঁচ নম্বর লেসনে আমরা `time.sleep()` আর sync DB ড্রাইভারের বিপদ নিয়ে যা লিখিতভাবে দেখলাম, সেটা যখন একটা বাস্তব প্রোডাকশন সিস্টেমের গল্প বা বেঞ্চমার্কের সাথে দেখানো হয় (যেমন একটা লোড টেস্টে দেখানো, একটা ভুল `time.sleep()` কীভাবে পুরো সার্ভারের throughput কমিয়ে দেয়), সেই ধারণাটা আরও গভীরভাবে গেঁথে যায় — কারণ শুধু "এটা ভুল" শোনার চেয়ে, "এটা ভুল আর সংখ্যায় ঠিক এতটা খারাপ" দেখাটা অনেক বেশি প্রভাবশালী।

এখানে একটা গুরুত্বপূর্ণ পরামর্শ দেয়া দরকার — ইউটিউবে এই ধরনের বিষয়ে ভিডিও খুঁজলে অসংখ্য ফলাফল পাবে, মানের তারতম্যও অনেক থাকবে। তাই ভিডিও বাছাই করার সময় কিছু জিনিস যাচাই করে নিও:

- ভিডিওটা কি বাস্তব কোড চালিয়ে দেখাচ্ছে, নাকি শুধু স্লাইড পড়ে যাচ্ছে? কোড চালিয়ে দেখানো ভিডিও সাধারণত বেশি স্পষ্ট হয়।
- ভিডিওটা কি নির্দিষ্টভাবে `asyncio`/FastAPI নিয়ে বলছে, নাকি পুরনো `threading`/`multiprocessing`-ভিত্তিক concurrency নিয়ে বলছে? দুটোই দরকারী, কিন্তু এই মডিউলের প্রসঙ্গে asyncio-নির্দিষ্ট কনটেন্টই বেশি উপকারী হবে।
- আলোচক কি ধাপে ধাপে এগোচ্ছেন (coroutine → task → event loop → Future), নাকি একসাথে অনেক ধারণা গুলিয়ে ফেলছেন? এই মডিউলে আমরা যেভাবে ধাপে ধাপে এগিয়েছি, সেই একই ধরনের ক্রমান্বয়িক ব্যাখ্যা খোঁজা ভালো।

সবচেয়ে গুরুত্বপূর্ণ কথা — এই ধরনের বাড়তি ভিডিও দেখাটা এই কোর্সের বিকল্প নয়, বরং সহায়ক। মূল ভিত্তিটা (GIL, coroutine, task, event loop, Future, blocking call-এর বিপদ) এই মডিউলেই তৈরি হয়ে গেছে; বাইরের ভিডিওগুলো শুধু সেই ভিত্তিটাকে আরও দৃঢ়, আরও বহুমাত্রিক করে তুলবে।

এই লেসন দিয়ে Module 5 সম্পূর্ণ হলো। আমরা শুরু করেছিলাম Python-এর GIL আর সেই থেকে asyncio-র প্রয়োজনীয়তা দিয়ে, তারপর coroutine, task, event loop, Future পেরিয়ে, FastAPI-এর ভেতরে সবচেয়ে বিপজ্জনক প্রোডাকশন ভুল (blocking call) চিনে, Git workflow আর multi-file প্রজেক্ট গঠন পর্যন্ত এসেছি। এখন আমাদের হাতে যথেষ্ট ভিত্তি তৈরি হয়ে গেছে সত্যিকারের API বানানো শুরু করার জন্য — পরের মডিউলে, **Module 6 — API Development Part One**-এ, আমরা status code, routing, আর POST request-এর গঠন নিয়ে হাতে-কলমে কাজ শুরু করবো।
