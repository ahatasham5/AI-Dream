# ML Learning Atlas

ML-এর বিষয়গুলো এক গাছে। নামে ক্লিক করলে সংজ্ঞা, হিসাব আর কোর্সের পাঠ।

**মূল পাতা এখন `../ml-mapping.html`।** ওটা এই folder থেকে তৈরি-করা ফাইল, সরাসরি বদলিও না। বদলাতে হবে `data/map.json`-এ, তারপর:

```bash
python3 atlas/build.py --out ml-mapping.html
```

পুরোনো হাতে-লেখা সংস্করণ `ml-mapping.backup.html`-এ রাখা আছে।

## ফোল্ডার

| পথ | কাজ |
|---|---|
| `data/map.json` | **মূল data।** সব node, প্রতিটার স্থির `id` সহ। বিষয় যোগ বা সংজ্ঞা বদলাতে এখানে হাত দাও |
| `data/shared.json` | একবারই-লেখা উপগাছ (এখন: Training-এর ১০ উপাদান)। `map.json`-এর `include` node এগুলো build-সময়ে ধরনে ধরনে কপি করে বসায়। **বদলাতে হলে শুধু এখানে** |
| `data/lessons.json` | কোন node থেকে কোর্সের কোন পাঠে যাবে। `"09/03"` = module-09-এর lecture-03 |
| `data/stories.json` | প্রতিটা node-এর গল্প (সমস্যা → ধারণা → তারপর কী) ও "কোন ক্ষেত্রে কোনটা"; নাম ধরে বসে |
| `data/history.json` | সূত্র-লিংকসহ যাচাই-করা ইতিহাস (https লিংক ছাড়া build থামে) |
| `data/practice.json` | "বাস্তবে কী হয়": scenario, **সূত্রে-মেলানো facts** (https সূত্র ছাড়া build থামে), অভিজ্ঞতা-ভিত্তিক typical/pitfalls, আর কোর্সে-নেই চিহ্ন |
| `data/path.json` | "গল্পের পথ"-এর অধ্যায় ও ধাপের ক্রম। গল্প নেই এমন node দিলে build থামে |
| `src/` | পাতার template, `style.css`, `app.js` |
| `build.py` | সব জুড়ে `dist/index.html` বানায় (একটাই ফাইল) |
| `merge_from_html.py` | `ml-mapping.html`-এ (পুরোনো ধরনে) হাতে যোগ করা node `map.json`-এ আনে। শুধু যা নেই তা যোগ করে, দুবার বসায় না। আগে dry-run দেখায়, `--apply` দিলে লেখে |
| `migrate_from_html.py` | একবারের কাজ ছিল: `ml-mapping.html` থেকে `map.json` বের করা। আবার চালালে `map.json` নতুন করে লেখা হবে (এখন `--force` ছাড়া থামে) |
| `dist/index.html` | তৈরি পাতা; খুলে দেখো বা publish করো |

## build

```bash
python3 atlas/build.py
```

publish-এর জন্য (কোর্সের `.md` ফাইল সঙ্গে না থাকলে স্থানীয় link ভেঙে যায়):

```bash
python3 atlas/build.py --lesson-base https://যেখানে-কোর্স-আছে/path   # পাঠ URL-এ যাবে
python3 atlas/build.py --no-lesson-links                              # পাঠ শুধু লেখা হয়ে থাকবে
```

build যাচাই করে: id অনন্য কি না, প্রতিটা node-এ নাম ও সংজ্ঞা আছে কি না, `lessons.json`-এর প্রতিটা পাঠ-path সত্যিই আছে কি না, আর পাঠ-তালিকার কোনো নাম মানচিত্রে না থাকলে সতর্ক করে।

## একই লেখা একাধিক জায়গায় (`ref`)

কোনো node-এ `"ref": "<অন্য node-এর id>"` দিলে ওই node-এর সংজ্ঞা, `trainingDetail`, `insight`, `selection`, `mathDetail` ইত্যাদি ধার নেয় (নিজের যে field আছে সেটা বদলায় না; children নিজেরটাই)। এতে একই model Task, Setting আর Model শাখায় এলে লেখা একবারই লিখতে হয়।

## একই উপগাছ একাধিক ধরনের ভেতরে (`include`)

Training-এর ১০ উপাদান (Target থেকে Learning Rate) From-scratch, Pretraining আর Fine-tuning, তিন ধরনেরই অংশ। পাঠক যাতে link ধরে ধরে হারিয়ে না যায়, তাই তিন জায়গাতেই গাছে দেখা যায়। কিন্তু লেখা আছে **একবারই**, `data/shared.json`-এ।

- `map.json`-এ ধরনের শেষে একটা node: `{"id": "ft-components", "include": "training-components", "id_suffix": "-in-ft", …}`। এতে নিজের `children` থাকতে পারে না।
- `build.py`-এর `expand_includes()` (`prepare()`-এর প্রথম কাজ) উৎসের কপি বসায়; কপির প্রতিটা id-র শেষে `id_suffix` জোড়ে। **`map.json` বদলায় না**, কপি শুধু memory-তে।
- `id_suffix` খালি (`""`) = মূল id। ওই কপিই "মূল" (এখন from-scratch-এরটা): গল্পের পথ, `ref`, alias, `#id` link মূল id ধরে থাকে।
- নাম একই, তাই নাম-ধরা গল্প, বাস্তব-স্তর আর পাঠ সব কপিতে একসাথে পৌঁছায়।
- উপাদানগুলো `kind: "info"` (ব্যাখ্যা, বাছার বিষয় নয়): পথ-গাছের "প্রতিটা leaf টাইপ-করা" নিয়ম মানে।
- নতুন উপাদান যোগ করতে `shared.json`-এ লেখো। তিন ধরনেই নিজে থেকে আসবে, আলাদা করে কিছু করতে হয় না।

## গাইড: বাকি আবশ্যক সিদ্ধান্ত

পথের ধরন (Fine-tune বা শূন্য থেকে Train) বাছলেই ওই মোডের **সব ধাপ জুড়ে** বাকি আবশ্যক সিদ্ধান্ত গোনা হয়, কোনো ধাপে কিছু না বেছেও (যেমন Fine-tune মোডে শুরুতেই ১২টা)।

- **topbar-এর pill** ("১২টা আবশ্যক বাকি →"): sticky, গাছের যত নিচেই থাকো দেখা যায়। চাপলে (বা কিবোর্ডে `N`) পরের অবাছা আবশ্যক সিদ্ধান্ত খুলে দেখায়, breadcrumb সেখানে সরে। শেষে ঘুরে প্রথমে ফেরে। সব হলে "✓ আবশ্যক সব হয়েছে"।
- **ধাপের চিহ্নে আম্বার সংখ্যা**: কোন ধাপে কয়টা আবশ্যক বাকি। panel ও গাছের ওপরের বারে একই গাইড, সাথে "চাইলে ঠিক করার n টা ঐচ্ছিক"।
- একই `group`-এর (যেমন training চালানোর দুই উপায়) একটা পূর্ণ হলে পুরোটা পূর্ণ, গোনায় একবারই। ঐচ্ছিক আর default-সহ কখনো গোনা হয় না।
- **সংখ্যা বাড়তেও পারে:** কিছু সিদ্ধান্ত শুধু আগের বাছাইয়ের পর আসে (LoRA বাছলে তার সেটিং, model-ধরন বাছলে তার checkpoint)। pill-এর tooltip-এ এটা লেখা। যুক্তি `engine.remaining/nextRequired`-এ, test সহ।

## একটা-একটা খোলা ও পথ-চেনা

বড় গাছে একে একে সব খুললে কোনটা কোন parent-এর, তা হারিয়ে যায়। তাই:

- **একটা-একটা খোলা (accordion, শুরুতে চালু):** একটা শাখা খুললে তার ভাইদের মধ্যে খোলাগুলো গুটিয়ে যায়। খোঁজা, "বাকি সিদ্ধান্ত" আর "ধাপে যাও"-তে পৌঁছালেও পথের প্রতিটা স্তরে একই নিয়ম। ওপরের বোতামে চালু/বন্ধ; অবস্থা browser-এ মনে থাকে। "সব খোলো" চাপলে এটা নিজে বন্ধ হয়, নইলে পরের ক্লিকে সব গুটিয়ে যেত। খোঁজা চলার সময় এটা কিছু গোটায় না।
- **খোলা পথ হাইলাইট:** যে node-এ আছো তার মূল পর্যন্ত রেখা accent রঙে।
- **sticky breadcrumb:** topbar-এর নিচে `Training › Fine-tuning › … › এই node`; যেকোনো অংশে ক্লিক করলে ওই স্তরে ফেরা যায় (নিচের সব গোটে)।
- **গোটানো শাখায় "✓ n টা বাছা":** গুটোলেও ভেতরে কী বেছেছো তা লুকায় না। সংখ্যা স্বাধীন সিদ্ধান্তের: checkpoint বাছলে তার model-ধরনও নিজে বাছা হয়, কিন্তু সেটা আলাদা গোনা হয় না (`engine.choiceIds`)। panel, বোতাম আর export-এও একই সংখ্যা।

যুক্তি `src/js/focus.js`-এ (DOM-মুক্ত, `tests/focus.test.js`-এ test); DOM বসানো `app.js`-এ। নতুন element-এ `id` বা function-এর নাম নিলে আগে দেখো কেউ নিয়েছে কি না: `PageSource` test দুবার-ঘোষণা আটকায়।

## নতুন node যোগ

### সংজ্ঞা লেখার নিয়ম

`definition` শুধু "কী" বলবে: সহজ বাংলা, আগে জিনিসটা সাধারণ কথায়, তারপর একটা ছোট উদাহরণ; অচেনা শব্দ আগে ব্যাখ্যা। "কোর্সে আছে", Module/Lecture নম্বর বা "এই মানচিত্রে…"-ধরনের কথা নয়; সংখ্যা দিলে অঙ্ক মিলিয়ে নেবে; নিশ্চিত না হলে নিরাপদ সাধারণ কথা। দৈর্ঘ্য ৬০–৪৫০ অক্ষর (test আটকায়)। `-sc` নকল ও `ref`-ওয়ালা node নিজে লেখে না; ভিত্তি node ঠিক করলেই হয়।

`map.json`-এ `name` আর `definition` লিখে `id` ফাঁকা রাখো (বা দিতেই পারো); `build.py` না থাকলে id বানিয়ে `map.json`-এ লিখে রাখে। এরপর id বদলিও না, বদলালে আগে শেয়ার করা `#id` link ভাঙবে।

## deep link

`dist/index.html#training` খুললে সরাসরি "৪. Training"-এর dialog খোলে। dialog-এর ভেতরে "link কপি" বোতাম আছে।

## ক্রমিক ধাপ (`seq`)

যেখানে সন্তানদের ক্রমে পড়লে বোঝা সহজ (Learning Setting-এর ধরন, Fine-tuning-এর অংশ, Architecture ইত্যাদি), সেখানে প্রতিটা সন্তানে `"seq": "১"`, `"২"`… আছে। গাছে নামের আগে নম্বর-বিল্লা দেখা যায়, dialog-এ "ধাপ ২ / ৫"। `build.py` যাচাই করে: কোনো সন্তানে `seq` থাকলে সবার থাকতে হবে, আর ১, ২, ৩… ক্রমে; নইলে build থামে। নাম বদলে নম্বর দেওয়া হয়নি, কারণ গল্প, পাঠ-link ও বাস্তব-স্তর নাম ধরে বসে।

## বাছাই-গাছ ও "আমার পথ" (planner)

গাছে নামতে নামতে বিকল্প বাছো, ডান পাশে পথ জমে, সেখান থেকে কপি করো। নোডের `kind` ঠিক করে সে গাছে কী:

| `kind` | মানে |
|---|---|
| `step` | পথের একটা ধাপ (যেমন "৪. পদ্ধতি ও memory-র হিসাব") |
| `decision` | একটা সিদ্ধান্ত। `pick`: `"one"` (একটা বাছো, অন্যটা বাছলে আগেরটা বাদ) বা `"many"`। সাথে `need` (নিচে) |
| `option` | বাছার মতো একটা পথ বা technique। `when` (কখন বাছবে), `basis` (`course` / `paper` / `experience` / `tool-doc`), `docs` |
| `info` | ব্যাখ্যামূলক node (সংজ্ঞা, গল্প); বাছা যায় না। বাছাইযোগ্য গাছের ভেতরে ধারণা-node এটাই |
| `tool` | কংক্রিট tool বা checkpoint। `tool`: `repo` (https), `license`, `archived`, `pushed`, `checked`, `src` বাধ্যতামূলক; `docs`, `supports`, `note` ঐচ্ছিক |

- option-এর সন্তান `decision` বা `tool`; tool-এর সন্তান `decision`। `build.py` এটা যাচাই করে।
- **আবশ্যক বনাম ঐচ্ছিক:** প্রতিটা `decision`-এ `need` (`required` বা `optional`) আর `needWhy` (এক লাইনে কারণ) থাকতেই হবে; `build.py` আটকায়। `required` না বাছলে "বাকি সিদ্ধান্ত"-এ আসে। `optional` আলাদা "চাইলে ঠিক করো" তালিকায় যায়। ঐচ্ছিক একটা-বাছার decision-এ `defaultOption` (তার একটা বিকল্পের id) দিলে না বাছায় pseudo-code-এ সেটা `‹সাধারণ মান›` চিহ্নে বসে। default শুধু সেখানেই দাও যেখানে বিকল্পের `when`-এ "ডিফল্ট/সাধারণ" প্রমাণ আছে। `group` (শুধু আবশ্যকে) দিলে একই group-এর যেকোনো একটা পূরণ হলে পুরোটা পূর্ণ (যেমন training চালানোর দুই উপায়)। ছাঁচে (`pseudo.json`) ঐচ্ছিক-default-হীন slot-এর লাইন `?slot` দিয়ে লেখো; test এটা আটকায়। `-sc` নকল ভিত্তির সাথে একই `need`/`group`/default রাখে (test আটকায়)।
- **পদ্ধতির নিজের অংশ (`part`):** option বা tool-এর ভেতরের node তিন রকম হতে পারে।
  - `part: "core"` (`kind: info`): ওই পদ্ধতির নিজেরই অংশ, যেমন SFT-র Input ও Target। parent বাছলে গাছে নিজে থেকে `✓ সাথে আছে` হয়ে যায়, না বাছলে ম্লান "… বাছলে আসে"। বাছা যায় না, "বাছা"-র সংখ্যাতেও গোনা হয় না। সবার আগে দেখায়।
  - `part: "optional"` (`kind: option`): পদ্ধতির ঐচ্ছিক অংশ, যেমন Instruction Tuning, LoRA Dropout। `বাছো` বোতাম আছে; বাছলে parent নিজে আসে, parent বাদ দিলে এটাও যায়। `when`, আর `guidance.json`-এ `why` ও `tradeoff` লাগে।
  - `part` ছাড়া `info`: শুধু-পড়ার ব্যাখ্যা (যেমন "Adapter save বনাম Merged save", যা আসলে অন্য সিদ্ধান্তকে বোঝায়)। বাছার সিদ্ধান্তের পাশে থাকলে ভাঁজ-করা "পড়ে বোঝো" অংশে যায়।
  - কোনটা কোন রকম, তা node-এর সংজ্ঞা পড়ে ঠিক করো; আন্দাজে `core` দিও না। `build.py` আকার যাচাই করে (`core` শুধু `info`-এ, `optional` শুধু `option`-এ, parent option বা tool)।
- নিচের বিকল্প বাছলে ওপরের বাছাইযোগ্য node-গুলোও নিজে থেকে বাছা হয়; `pick: one`-এ ভাই-বোনের একটা বাছলে বাকিরা বাদ।
- ডান পাশ থেকে কপি: Markdown, JSON (id সহ, ভবিষ্যতে code তৈরির জন্য), সাধারণ লেখা, শেয়ার-লিংক (`#plan=id1,id2,...`)। বাছাই শুধু এই browser-এ জমা থাকে।
- tool-এর তথ্য পুরোনো হয়। `python3 atlas/verify_tools.py` আবার GitHub/Hugging Face থেকে মিলিয়ে অমিল জানায় (লগইন ছাড়া ঘণ্টায় ৬০ অনুরোধ; `GITHUB_TOKEN` দিলে বেশি)।
- নতুন tool যোগ: `map.json`-এ `kind: "tool"` node, `tool.checked` তারিখ দিয়ে। আন্দাজে licence বা "চালু আছে" লিখো না।

### পথের ধরন (mode) ও ধাপ

- শাখা "৭. আমার পথ বানাও" আর পাতার ওপরের শুরু-বারে প্রথম প্রশ্ন: **Fine-tune করব, না শূন্য থেকে Train?** এই দুটো `option`-এ `steps: [step-id, ...]` আছে, যার ক্রমই পথের ধাপ-তালিকা।
- mode-option-এর নিচে `kind: "stepref"` সারি (`goto: step-id`, `seq` নম্বর): চাপলে আসল step-node-এ গিয়ে খোলে। ধাপ নকল করা হয়নি, তাই শেখার গাছ আর পথ-গাছ এক সূত্রে।
- শুরু-বার ও ডান-তালিকায় ধাপ-চিপ: কোন ধাপে কয়টা বাছা (✓), চাপলে ওই ধাপে যায়।
- নতুন mode বা নতুন ধাপ: step-node বানাও (`kind: "step"`), mode-option-এর `steps`-এ id বসাও, আর `stepref` সারি দাও। `build.py` যাচাই করে `goto` ও `steps` সত্যিই step-এ পৌঁছায় কি না।
- একই বিকল্প (যেমন memory কৌশল, serving engine) দুই mode-এ দরকার হলে node-টা clone করে `-sc`-ধরনের প্রত্যয়ী id দিয়ে বসানো হয় (নাম এক, তাই গল্প ও পাঠ-link নিজে থেকে আসে)।

### এক গাছ, দুই স্তর নয়

Fine-tuning (আর From-scratch)-এর গাছ আলাদা "ধাপের গাছ" ছাড়া একটাই: ধাপ (`step`) → সিদ্ধান্ত (`decision`) → বিকল্প (`option`) → tool, আর পাশে ব্যাখ্যা (`info`)। নতুন বিকল্প যোগ করতে আসল ধারণা-node-কেই `kind: "option"` দাও (গল্প, পাঠ-link, বাস্তব-স্তর নাম ধরে নিজে আসে); আলাদা নকল node বানিও না।
**বাছার নিয়ম:** `decision`-এ `pick: "one"` (ডিফল্ট ভাবো, প্রতি সিদ্ধান্ত থেকে একটাই), শুধু যেখানে সত্যিই জমা হয় (মাপকাঠি, memory কৌশল, tracking) `pick: "many"`। বাছাই-ক্রম মুক্ত; ডান-তালিকা গাছের ক্রমে সাজায়।

### Architecture: কাঠামো, token mixer, ছক (দুই স্তর)

"model-এর পরিবার" একটা সারিতে MLP, CNN, Transformer, Mamba রাখলে hybrid-এর ঘর থাকে না, কারণ Transformer ও Mamba আসলে **একই কাঠামোর** (block-stack) দুই রকম **ভেতরের অংশ** (mixer)। তাই বাছাই-গাছে (`sc-arch`) স্তর দুটো আলাদা:

1. **কাঠামো** (`sc-family`, একটা বাছো): MLP, CNN, RNN, Block-stack।
2. **Block-stack বাছলে** ভেতরে: `sc-mixer` (**একাধিক বাছা যায়**: Full attention, Linear attention পরিবার, SSM পরিবার; ২টা বাছলেই hybrid), `sc-layout` (সব layer এক ধরন / interleave / parallel head), `sc-ffn` (dense বা MoE)।
3. **প্রতিটা mixer-এর নিজের রূপ ও সরঞ্জাম তার ভেতরেই** নেস্টেড: Full attention-এর নিচে অবস্থান-তথ্য, attention-এর দক্ষতা, implementation; Linear attention-এর নিচে `sc-linear-kind` ও `sc-linear-impl`; SSM-এর নিচে `sc-ssm-kind` ও `sc-ssm-impl`। কোনো mixer না বাছলে এগুলো আসেই না, তাই "(Transformer হলে)"-ধরনের লেখা আর লাগে না।
4. **নিয়ম** (`rules.json`): দুই mixer বাছলে `sc-layout`-এ interleave বা parallel আবশ্যক (`requires`), আর uniform বাছলে বিরোধ (`conflict`)। জোড়া ধরে লেখা, তাই নতুন mixer যোগ করলে তার জোড়ার নিয়মও যোগ করো।

**নতুন mixer (যেমন একটা নতুন linear-attention রূপ) যোগ করার ধাপ:**
- Reference গাছে `recurrent-alternatives` বা `state-space-models`-এর নিচে node: সংজ্ঞা, `mathDetail` (সূত্র, চিহ্নের অর্থ, ছোট সংখ্যার উদাহরণ), `insight`। প্রতিটা সংখ্যা paper বা model card থেকে মিলিয়ে।
- বাছাই-গাছে `sc-linear-kind` (বা `sc-ssm-kind`)-এ `kind: option`, `ref: <reference id>`, `when`, `basis`। `guidance.json`-এ `why` ও `tradeoff`; `pseudo.json`-এর `options`-এ ছোট ইংরেজি লাইন।
- `practice.json`-এ `facts` (সূত্র-লিংকসহ), `history.json`-এ সাল। যা যাচাই হয়নি, তা লিখো না, বা "অনুমান" বলে লেখো।

**Hybrid model যোগ করতে:** `hybrid-architectures`-এর নিচে node (সংজ্ঞায় layer-ভাগ ও ছক, যেমন "প্রতি ৪ layer-এ ৩টা সস্তা, ১টা attention")। সংখ্যা model card বা `config.json` থেকে, নিজে গুনে নয় (গুনলে বলে দাও)। **রূপান্তরের পদ্ধতি** যোগ করতে `architecture-conversion`-এর নিচে; **নতুন খোলা প্রশ্ন** `arch-open-problems`-এর নিচে, আর প্রতিটার পাশে অন্তত একটা সূত্র-লিংকওয়ালা fact, নইলে রাখা হয় না।

### তুলনা (একই parent-এর ভাইদের পাশাপাশি)

যেকোনো node-এর ভাই থাকলে (শাখা হোক বা leaf) তাদের পাশাপাশি তুলনা করা যায়, শুধু **একই parent-এর ভেতরে**।

- **ঢোকার দুই দরজা:** (১) গাছে parent-এর সারিতে "⇄ তুলনা" (hover বা focus করলে দেখা যায়, যাতে গাছ ভিড় না হয়); (২) যেকোনো node-এর dialog-এ "⇄ ভাইদের সাথে তুলনা" বা "⇄ ভেতরের N টা তুলনা করো"।
- **কে তুলনার যোগ্য** (`src/js/compare.js`, DOM-মুক্ত, Node-এ test): step নয়, stepref নয়, `seq` (ক্রমিক নম্বর) নেই। নম্বর-ওয়ালারা সাধারণত ক্রমিক অংশ, বিকল্প নয়। একটা parent-এ ২টার কম যোগ্য ভাই থাকলে তুলনা নেই।
- **নম্বর থাকলেও যেগুলো আসলে বিকল্প** (Task, Learning Setting, Architecture-এর ধরন, Training-এর তিন ধরন…): নম্বর শুধু তালিকার ক্রম। এমন parent-এ `"compare": "alternatives"` দাও, তাহলে নম্বর-ওয়ালা সন্তানও তুলনায় আসে। মিশ্র তালিকায় (যেমন Supervised Learning: Input, Target, Model শেখা ক্রমিক; তিন ধরনের target বিকল্প) ক্রমিক সন্তানে `"peer": false`। নম্বর দেখে আন্দাজ করা হয় না: কোনটা কোন রকম, সংজ্ঞা পড়ে ঠিক করো। `build.py` ও test আকার আটকায়।
- তুলনা নেই এমন শাখার সারিতে (২+ সন্তান) hover করলে "বিকল্প নয়" লেখা দেখায়, যাতে চুপচাপ না থাকে।
- **একবারে কত, তা ব্যবহারকারী ঠিক করে:** শুরুর মান ৪, "একসাথে সর্বোচ্চ − ৪ +" দিয়ে ২ থেকে ৮ (browser-এ মনে থাকে)। **কোনগুলো** দেখবে সেও ব্যবহারকারীর: chip চেপে বাছো/বাদ দাও। ভরে গেলে নতুন chip চাপলে সবচেয়ে আগে বাছাটা নিজে সরে যায় (বার্তাসহ), তাই আগে হাতে বাদ দিতে হয় না। সংখ্যা কমালে সবচেয়ে নতুনগুলো থাকে।
- **সারি node-এর যা আছে তা থেকেই তৈরি** (সংজ্ঞা, সমস্যা ও ধারণা, কখন/কেন/দাম, সূত্র ও ছোট হিসাব, কীভাবে শেখে, tool-এর তথ্য, ভেতরের গঠন, বাস্তবে কী হয়)। কারও না থাকলে সারিই আসে না; কোনো কলামে না থাকলে "—"।
- **"তথ্যের ভিত্তি" সারি নেই:** "কোর্সে আছে" পাঠকের কাজের তথ্য নয়, তাই কোথাও দেখানো হয় না (node-dialog-এও না)। শুধু আসল সূত্র বা সতর্কতা (paper থেকে মেলানো, tool-এর docs, "অভিজ্ঞতা-ভিত্তিক, নিয়ম নয়") থাকলে টেবিলের **শেষে** ছোট টীকা। নতুন সারি যোগ করতে `compare.js`-এর `SPEC`-এ একটা লাইন।
- **"শুধু যেখানে ফারাক আছে"** টিক দিলে হুবহু-এক সারি লুকোয়। কোনো কলামে মান না থাকলে সেটা ফারাক ধরা হয়।
- প্রতিটা কলামে **খোলো** (পুরো পাতা; বন্ধ করলে তুলনায় ফেরা), **পথে বাছো** (option/tool হলে; engine-এর নিয়ম একই), **✕ বাদ**।
- **শেয়ার-link:** `#cmp=id1,id2,…`। ভুল id বা ভিন্ন parent-এর id নিরাপদে সামলানো হয়।

### Pseudo-code (বাছা পথ থেকে)

ডান-তালিকায় "Pseudo-code দেখো" আর "Pseudo-code কপি": বাছা পথ থেকে framework-নিরপেক্ষ pseudo-code, ধাপ-ক্রমে। এটা real code বা কোনো library-র API নয়; কোন ধাপে কী ঘটে তার বর্ণনা, তাই যেকোনো framework-এ বোঝা যায়। **অবাছা সিদ্ধান্ত `‹? …›` চিহ্নে থাকে**, বাছলে লেখা নিজে বদলায়।

- ছাঁচ ও লেখা `data/pseudo.json`-এ: `slots` (সিদ্ধান্ত-id → slot), `options` (বিকল্প-id → লেখা, বা `{slot: লেখা}` যখন এক বিকল্প একাধিক জায়গা ভরে, যেমন শেখার সংকেত সংকেত ও loss দুটোই বসায়), `templates` (mode-id → লাইন)।
- ছাঁচের লাইনে `{{slot}}`; `?slot লাইন` ঐচ্ছিক (slot ফাঁকা থাকলে বাদ), `!slot লাইন` শুধু slot ফাঁকা থাকলে। অনেক-লাইনের slot আলাদা লাইনে খোলে।
- নতুন সিদ্ধান্ত যোগ করলে `slots`-এ তার id বসাও; বিকল্পের লেখা না দিলে নামই বসে। `build.py` ও test যাচাই করে: অজানা id, label-হীন slot, কেউ ভরে না এমন slot।
- OCR একটা উদাহরণ মাত্র, একমাত্র নয়: মানচিত্রটা সার্বজনীন শেখার জন্য। তাই ছবি-শ্রেণিবিন্যাস, speech, ছকের data, regression ইত্যাদির সমান-মানের বিকল্পও আছে; কোনো একটা ক্ষেত্রের গভীরতা দিয়ে মানচিত্র ভরো না।

### বিরোধ ও নির্ভরতা (`data/rules.json`)

ডান-তালিকায় "সতর্কতা ও বিরোধ", আর pseudo-code ও Markdown-এর মাথায়ও। নিয়ম তিন ধরনের:

- `conflict` (লাল): `if`-এর সব বাছা, আর `with`-এর কোনো একটা বাছা থাকলে (যেমন merge করে deploy + merge-হয়-না adapter)।
- `warn` (সতর্কতা): একই গঠন, কিন্তু চলে, শুধু সাবধান থাকতে হয় (যেমন quantized base-এ merge)।
- `requires` (অ্যাম্বার): `if` বাছলে `anyOf`-এর অন্তত একটা লাগে (যেমন preference optimization বাছলে data-ছাঁচ 'তুলনা-জোড়া')।

প্রতিটা নিয়মে `src` (course-এর lecture বা paper) আর `path` বা `url` বাধ্যতামূলক। আন্দাজের নিয়ম যোগ করো না: `build.py` ও test যাচাই করে id, সূত্র, পাঠ-ফাইল আছে কি না।
একই `pick: one` সিদ্ধান্তের দুই ভাইয়ের জন্য নিয়ম লাগে না, সেটা engine আগেই আটকায়।

### লিংক-যাচাই

`python3 atlas/verify_links.py` সব বাইরের https লিংক (tool-এর repo/docs, practice-এর সূত্র, `how`, ইতিহাস, নিয়ম) জীবিত কি না দেখে। bot-আটকানো সাইট (403/429) "অনিশ্চিত" হিসেবে আলাদা। CI-তে সাপ্তাহিক চলে।
