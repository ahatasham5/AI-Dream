# Lecture 01 — Pixel ও Channel: ছবি মানে সংখ্যার ছক

> আগে যা জানা থাকলে ভালো: সংখ্যাকে সারি ও কলামের ছকে সাজানো যায় — [shape-এর ধারণা](../module-09-model-architecture/lecture-07-shapes-and-parameter-count.md)। এই lecture শেষে পারবে: একটা ছবি কীভাবে সংখ্যার ছক হিসেবে থাকে তা বলতে এবং Python list-এ লিখতে।

## সমস্যাটা কী?

এতদিন model-কে আমরা সংখ্যা দিয়েছি: `x = 3`, বা `[2, 1]`। কিন্তু একটা ছবি তো সংখ্যা নয়, সেটা একটা দৃশ্য। কম্পিউটার চোখ দিয়ে দেখে না; সে শুধু সংখ্যা নিয়ে হিসাব করতে পারে। তাই ছবি model-এ ঢোকানোর আগে প্রথম কাজ হলো ছবিটাকে সংখ্যায় বদলানো। এটা না বুঝলে পরের সব lecture আটকে যাবে।

## ধারণাটা সহজ ভাষায়

ফোনে একটা ছবি অনেকখানি zoom করলে ছোট ছোট বর্গ দেখা যায়। প্রতিটা বর্গ একটা **pixel** — ছবির সবচেয়ে ছোট বিন্দু। পুরো ছবি হলো সারি ও কলামে সাজানো অনেক pixel।

**সাদা-কালো (grayscale) ছবিতে** প্রতিটা pixel-এ থাকে একটা সংখ্যা, `0` থেকে `255`-এর মধ্যে:

- `0` মানে কালো
- `255` মানে সাদা
- মাঝের সংখ্যা মানে ধূসর; যত বড়, তত উজ্জ্বল

একটা ৩×৩ ছবি তাই এমন একটা ছক:

```text
  0    0  255
  0  128  255
  0    0  255
```

বাঁ দিকের দুই কলাম কালো, ডান কলাম সাদা, মাঝখানে একটা ধূসর বিন্দু। ছবি আর সংখ্যার ছক এখানে একই জিনিস।

**রঙিন ছবিতে** একটা সংখ্যায় রং বোঝানো যায় না। তাই প্রতিটা pixel-এ থাকে তিনটা সংখ্যা: লাল (R), সবুজ (G), নীল (B) কতটুকু আছে। এই তিনটা আলাদা সংখ্যার স্তরকে বলা হয় **channel**।

| রং | [R, G, B] |
|---|---|
| লাল | [255, 0, 0] |
| সবুজ | [0, 255, 0] |
| সাদা | [255, 255, 255] |
| কালো | [0, 0, 0] |

সাদা-কালো ছবির channel ১টা, রঙিন ছবির ৩টা। তাই একটা রঙিন ছবির সংখ্যার সংখ্যা = `সারি × কলাম × ৩`।

Python-এ index গোনা শুরু হয় `0` থেকে, তাই `gray[1][1]` মানে দ্বিতীয় সারির দ্বিতীয় pixel।

## ছোট একটা উদাহরণ

নিচের কোডে ৩×৩ সাদা-কালো ছবি আর ২×২ রঙিন ছবি nested list হিসেবে লেখা হয়েছে। রঙিন ছবিটাকে তিনটা channel-এর তিনটা আলাদা ছকে ভাগও করা হয়েছে।

```python
# 3x3 grayscale image: 0 = black, 255 = white
gray = [
    [0,   0, 255],
    [0, 128, 255],
    [0,   0, 255],
]
print("rows x cols:", len(gray), "x", len(gray[0]))
print("pixel at row 1, col 1:", gray[1][1])
print("128 scaled to 0-1:", round(128 / 255, 3))

# 2x2 color image: each pixel = [R, G, B]
rgb = [
    [[255, 0, 0], [0, 255, 0]],
    [[0, 0, 255], [255, 255, 255]],
]
for c, name in enumerate(["R", "G", "B"]):
    grid = [[pixel[c] for pixel in row] for row in rgb]
    print(name, grid)
print("total numbers:", 2 * 2 * 3)
```

```text
# output:
rows x cols: 3 x 3
pixel at row 1, col 1: 128
128 scaled to 0-1: 0.502
R [[255, 0], [0, 255]]
G [[0, 255], [0, 255]]
B [[0, 0], [255, 255]]
total numbers: 12
```

রঙিন ছবির চার pixel হলো লাল, সবুজ, নীল, সাদা। R channel-এর ছকে `255` আছে লাল ও সাদা pixel-এর জায়গায়, তাই `[[255, 0], [0, 255]]`। চার pixel × ৩ channel = ১২টা সংখ্যা।

একটা ছোট কথা: `128 / 255 = 0.502` — অনেক model `0..255`-এর বদলে `0..1`-এর মানে কাজ করে। এই রূপান্তর [Lecture 07](lecture-07-resize-and-preprocessing.md)-এ বিস্তারিত আসবে।

## মনে রাখার সারকথা

- ছবি হলো pixel-এর ছক; সাদা-কালো ছবিতে প্রতিটা pixel একটা সংখ্যা (`0` কালো থেকে `255` সাদা)।
- রঙিন ছবিতে প্রতিটা pixel-এ ৩টা সংখ্যা: R, G, B — এই তিনটা স্তরের নাম channel।
- ছবি model-এ ঢোকে সংখ্যা হিসেবেই; "ছবি বোঝা" মানে এই সংখ্যাগুলো নিয়ে হিসাব।

## নিজে করো

১. ২×২ রঙিন ছবিতে মোট কয়টা সংখ্যা থাকে? ১০×১০ সাদা-কালো ছবিতে?
২. `[255, 255, 0]` pixel-টা কোন রঙের কাছাকাছি? (ইঙ্গিত: লাল ও সবুজ একসঙ্গে পুরো জ্বললে কী হয়?)
৩. `[[0, 200], [130, 255]]` ছবিতে কয়টা pixel-এর মান `128` বা তার বেশি?

২. লাল ও সবুজ একসঙ্গে পুরো জ্বললে হলুদ হয়, তাই এটা হলুদ।
৩. `200`, `130`, `255` — এই তিনটা `128`-এর বেশি; `0` নয়। উত্তর ৩টা।
