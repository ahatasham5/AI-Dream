## সমস্যাটা কী?

Agent যদি সবসময় নিজের বর্তমান অনুমানের সেরা চালটাই দেয়, তাহলে ঘটনাচক্রে প্রথমে যে চাল একটু ভালো দেখায় সে তাতেই আটকে যেতে পারে। যে চালটা আসলে আরও ভালো, তার ফল কখনো সে দেখেই না। তাই অনুমান ঠিক করার জন্য নতুন চাল চেষ্টা করাও দরকার।

## ধারণাটা সহজ ভাষায়

একটা মেশিনে দুটো বোতাম। বোতাম A চাপলে **সবসময় 1** পাওয়া যায়। বোতাম B চাপলে **30% সময় 10, বাকি সময় 0** পাওয়া যায়, অর্থাৎ গড়ে 3। B আসলে ভালো। কিন্তু agent তা জানে না। সে প্রতি বোতামের এখন পর্যন্ত পাওয়া reward-এর গড়কে Q ধরে, শুরুতে দুটোই 0।

প্রথমে সে A চেপে 1 পেল। Q(A) = 1, Q(B) = 0। এরপর "সেরা" বলতে A-ই, তাই সে আর কখনো B চাপে না। B-র 3 গড় তার অজানাই থেকে যায়। এই সমস্যার নাম **exploitation বনাম exploration**: যা জানি তা কাজে লাগানো (exploit), না নতুন কিছু চেষ্টা করা (explore)।

সবচেয়ে সহজ সমাধান **ε-greedy** (ε = এপসিলন)। প্রতিবার:

- ε সম্ভাবনায় একটা এলোমেলো action নাও (explore),
- বাকি সময় বর্তমান সেরা action নাও (exploit)।

ε সাধারণত ছোট, যেমন 0.1। অভিজ্ঞতা বাড়লে অনেক সময় ε ধীরে কমানো হয়।

## ছোট একটা উদাহরণ

১০০০ বার চেপে দেখা যাক, ε-র তিনটা মানে (seed স্থির):

```python
import random

def pull(arm):
    if arm == "A":
        return 1.0
    return 10.0 if random.random() < 0.3 else 0.0

def run(eps, steps=1000, seed=1):
    random.seed(seed)
    q, n, total = {"A": 0.0, "B": 0.0}, {"A": 0, "B": 0}, 0.0
    for _ in range(steps):
        if random.random() < eps:
            arm = random.choice(["A", "B"])
        else:
            arm = max(q, key=q.get)
        r = pull(arm)
        n[arm] += 1
        q[arm] += (r - q[arm]) / n[arm]      # এখন পর্যন্ত গড়
        total += r
    return round(total / steps, 2), n, {k: round(v, 2) for k, v in q.items()}

for eps in [0.0, 0.1, 0.3]:
    print("eps", eps, run(eps))
# output:
# eps 0.0 (1.0, {'A': 1000, 'B': 0}, {'A': 1.0, 'B': 0.0})
# eps 0.1 (2.66, {'A': 157, 'B': 843}, {'A': 1.0, 'B': 2.97})
# eps 0.3 (2.45, {'A': 161, 'B': 839}, {'A': 1.0, 'B': 2.73})
```

| ε | গড় reward | B চাপা হয়েছে | B-র Q (সত্যি গড় 3) |
|---|---|---|---|
| 0 | 1.00 | 0 বার | 0 (কখনো জানেনি) |
| 0.1 | 2.66 | 843 বার | 2.97 |
| 0.3 | 2.45 | 839 বার | 2.73 |

ε = 0 হলে agent A-তেই আটকে থাকে। ε = 0.1 হলে সে B-র আসল মান প্রায় ঠিক শিখে ফেলে। ε = 0.3-এ গড় reward আবার কমে, কারণ এলোমেলো চালে খরচ হচ্ছে। তাই ε-র মান মাঝামাঝি ছোট রাখা হয়। (গড়গুলো এই seed-এর সিমুলেশন, তাই অন্য seed-এ সামান্য আলাদা হবে।)

## On-policy ও Off-policy

দুটো আলাদা নিয়ম আছে:

- **Behavior policy:** যে নিয়মে agent আসলে চাল দেয় ও data জমায়। (ε-greedy)
- **Target policy:** যে policy-কে আমরা ভালো করতে চাই বা যার মান অনুমান করছি।

যদি দুটো একই হয়, শেখাটা **on-policy**। আলাদা হলে **off-policy**।

কী আলাদা হয়, একটা হিসাবে দেখা যাক। এক step: reward r = 1, γ = 0.9। Next state-এ Q(ডান) = 6, Q(বাঁ) = 3। ε-greedy-র ঘটনাচক্রে agent next state-এ "বাঁ" চাল দিল। পুরোনো Q = 2, α = 0.1।

| পদ্ধতি | target কীভাবে বানায় | target | নতুন Q |
|---|---|---|---|
| **Q-learning** (off-policy) | next state-এর সেরা Q ধরে, যে চালই নেওয়া হোক | 1 + 0.9 × 6 = 6.4 | 2 + 0.1 × (6.4 − 2) = 2.44 |
| **SARSA** (on-policy) | next state-এ যে চাল আসলে নেওয়া হলো তার Q | 1 + 0.9 × 3 = 3.7 | 2 + 0.1 × (3.7 − 2) = 2.17 |

Q-learning শেখে "সবসময় সেরা চাল নিলে কত পাওয়া যেত", এলোমেলো চাল নেওয়া সত্ত্বেও। তাই Lecture 04-এ এলোমেলো চালের data থেকেও ভালো policy শেখা গিয়েছিল। SARSA শেখে "যেভাবে আমি আসলে চলছি (ভুল-সহ), সেভাবে কত পাওয়া যাবে"।

Off-policy-র সুবিধা: পুরোনো data, জমানো অভিজ্ঞতা বা অন্যের log থেকে শেখা যায়। অসুবিধা: data যে policy বানিয়েছে আর যে policy শিখছে, দুটোর ফারাক বেশি হলে অনুমান ভুল হতে পারে। On-policy-তে data সবসময় বর্তমান policy-র নিজের, তাই শেখা স্থির থাকে। কিন্তু প্রতি update-এর পরে নতুন data বানাতে হয়, যা খরচ বাড়ায়।

এই ভেদ পরে কাজে লাগবে। PPO ও GRPO নিজের সদ্য বানানো উত্তর থেকে শেখে (প্রায় on-policy), আর DPO আগে জমানো preference-জোড়া থেকে শেখে (offline)। পুরোনো আর নতুন policy অল্প আলাদা হলে তা কীভাবে সামলানো হয়, [Lecture 07](lecture-07-actor-critic-and-ppo.md)-এ।

## মনে রাখার সারকথা

- Agent শুধু সেরা অনুমানের চাল দিলে আরও ভালো চাল কখনো জানতে পারে না; ε-greedy মাঝে মাঝে এলোমেলো চাল দিয়ে এটা ঠেকায়।
- ε খুব ছোট হলে আটকে যায়, খুব বড় হলে খরচ বাড়ে।
- On-policy: যে policy চলছে তার data থেকেই শেখা; off-policy: অন্য policy-র data থেকে শেখা। Q-learning off-policy, SARSA on-policy।
