# Lecture 03 — Return, Discount ও Delayed Reward

> আগে যা জানা থাকলে ভালো: [Lecture 02](lecture-02-agent-environment-state-action-reward.md)-এর করিডোরের episode আর তার reward-এর সারণি। এই lecture শেষে পারবে: reward-এর তালিকা থেকে discount-সহ return হাতে বের করতে, আর বলতে কেন দেরিতে আসা reward-কে ছোট করে ধরা হয়। ([Map-এ অবস্থান](../01-learning-map.md): RL-এর objective, অর্থাৎ কী বাড়াতে হবে, সেটা এখানে ঠিক হয়।)

## সমস্যাটা কী?

Lecture 02-এ দুটো পথ দেখা গেছে: সোজা তিন চালে শেষ ঘরে পৌঁছানো (reward-এর যোগফল 8), আর ঘুরে পাঁচ চালে পৌঁছানো (যোগফল 6)। যোগফলেই দ্রুত পথ জিতেছে। কিন্তু অনেক কাজে প্রশ্নটা আরও কঠিন। ক্রিকেটে প্রতি বলে ১-২ রান পাওয়া যায়, আর ম্যাচ জেতার আসল পুরস্কার আসে শেষ বলে। এখনকার ছোট লাভ নেব, না পরের বড় লাভের জন্য অপেক্ষা করব? এখনকার reward আর দেরির reward-কে একই পাল্লায় মাপার একটা নিয়ম দরকার।

## ধারণাটা সহজ ভাষায়

নিয়মটা সহজ: **দেরিতে আসা reward-কে একটু ছোট করে ধরো।** প্রতি এক ধাপ দেরির জন্য reward-কে একই সংখ্যা দিয়ে গুণ করা হয়। এই সংখ্যার নাম **discount factor**, আমরা লিখব **γ** (গামা)। সাধারণত γ 0 থেকে 1-এর মাঝে থাকে; এই course-এ 0.9 ব্যবহার করব।

γ = 0.9 হলে:

| reward কত ধাপ পরে | কত দিয়ে গুণ হয় |
|---|---|
| এখনই | 1 |
| 1 ধাপ পরে | 0.9 |
| 2 ধাপ পরে | 0.81 |
| 3 ধাপ পরে | 0.729 |
| 4 ধাপ পরে | 0.656 |

এভাবে ছোট করা reward-গুলো যোগ করলে যা পাওয়া যায়, তার নাম **return**। Return হলো "এই চাল থেকে শুরু করে আমি মোট কতটা পুরস্কার পেলাম, দেরির জন্য ছাড় দিয়ে।" RL-এর লক্ষ্য একটা reward নয়, return বাড়ানো।

Discount কেন? দেরির reward অনিশ্চিত, মাঝপথে অনেক কিছু বদলাতে পারে। আর discount থাকলে একই ফল দ্রুত পাওয়া কাজটা বেশি দামি হয়। Lecture 02-এর −1 সময়-খরচের সঙ্গে এটা একই দিকে কাজ করে।

## ছোট একটা উদাহরণ

### ১. Lecture 02-এর episode

Reward-এর তালিকা: `[−1, −1, −1, −1, 10]`, γ = 0.9।

| step | reward | গুণক | ছোট করা reward |
|---|---|---|---|
| 0 | −1 | 1 | −1 |
| 1 | −1 | 0.9 | −0.9 |
| 2 | −1 | 0.81 | −0.81 |
| 3 | −1 | 0.729 | −0.729 |
| 4 | 10 | 0.656 | 6.561 |

যোগ করলে: −1 − 0.9 − 0.81 − 0.729 + 6.561 = **3.122**।

সোজা পথের `[−1, −1, 10]`-এর return: −1 − 0.9 + 0.81 × 10 = **6.2**। Discount ছাড়া ফারাক ছিল 8 বনাম 6; discount-সহ 6.2 বনাম 3.122। দ্রুত পথ আরও স্পষ্টভাবে এগিয়েছে।

### ২. এখনই ছোট, নাকি পরে বড়?

পথ A: reward `[2, 0, 0, 0]` (এখনই 2)। পথ B: `[0, 0, 0, 10]` (তিন ধাপ পরে 10)।

| γ | A-এর return | B-এর return |
|---|---|---|
| 0.9 | 2 | 10 × 0.729 = 7.29 |
| 0.5 | 2 | 10 × 0.125 = 1.25 |

γ বড় হলে agent ধৈর্যশীল, B ভালো। γ ছোট হলে অধৈর্য, A ভালো। γ = 0 হলে শুধু এখনকার reward দেখা হয়।

### ৩. প্রতিটা step-এর return পিছন থেকে

Lecture 02-এর episode-এর প্রতিটা step থেকে return আলাদা করে বের করা যায়। শেষ step-এর return তার reward-ই। তার আগের step-এর return: **নিজের reward + γ × পরের step-এর return**।

| step | হিসাব | return |
|---|---|---|
| 4 | 10 | 10 |
| 3 | −1 + 0.9 × 10 | 8 |
| 2 | −1 + 0.9 × 8 | 6.2 |
| 1 | −1 + 0.9 × 6.2 | 4.58 |
| 0 | −1 + 0.9 × 4.58 | 3.122 |

শেষে 3.122-ই এসেছে, ১-এর হিসাবের সঙ্গে মিলল। এই "নিজের reward + γ × পরেরটা" ধরনের হিসাবটা Lecture 04-এর Q-learning-এর ভিত্তি।

দুটো জিনিস দেখার আছে:

- Step 0-এর reward ছিল −1, কিন্তু তার return 3.122 (ধনাত্মক)। কারণ ওই চালের পরে যা যা ঘটেছে, শেষের +10 সহ, সবই তার return-এ ঢুকেছে। এভাবেই শেষে আসা reward আগের চালগুলোর কাছে পৌঁছায়। একে বলে **credit assignment**: শেষের ফলের কৃতিত্ব আগের কোন চালের, সেটা ভাগ করা।
- Step 0 আর step 2 দুটোতেই state 0, action "ডান"। কিন্তু return 3.122 আর 6.2, কারণ পরে কী ঘটল তা আলাদা (step 1-এ ফিরে গিয়েছিল)। তাই একটা (state, action)-এর "মান" বলতে অনেক episode-এর return-এর গড় ধরতে হয়। সেটা পরের lecture।

## Formula ও কোড

Reward-এর তালিকা `r0, r1, r2, …` হলে, একটা step থেকে return:

`return = r0 + γ × r1 + γ² × r2 + γ³ × r3 + …`

এখানে `γ²` মানে γ × γ। γ = 0.9 হলে γ² = 0.81, γ³ = 0.729। এটাই উপরের তালিকার গুণকগুলো। পিছন থেকে হিসাবের রূপ: `return = r0 + γ × (পরের step-এর return)`। কোডে:

```python
rewards = [-1, -1, -1, -1, 10]   # Lecture 02-এর episode
gamma = 0.9

G, returns = 0.0, []
for r in reversed(rewards):         # শেষ থেকে শুরুর দিকে
    G = r + gamma * G
    returns.append(round(G, 3))
returns.reverse()
print(returns)
# output:
# [3.122, 4.58, 6.2, 8.0, 10.0]
```

## মনে রাখার সারকথা

- Return = এখন থেকে পরের সব reward-এর যোগফল, প্রতি ধাপ দেরির জন্য γ গুণ করে ছোট করে।
- γ বড় (1-এর কাছে) মানে ধৈর্যশীল, γ ছোট মানে এখনকার reward-এর দিকে ঝোঁক।
- Return-এর পিছন থেকে হিসাব: `নিজের reward + γ × পরের return`; এভাবে শেষের reward আগের চালে পৌঁছায়।
